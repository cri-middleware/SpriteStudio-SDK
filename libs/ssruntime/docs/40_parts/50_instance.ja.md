# インスタンスパーツ

インスタンスパーツは、別のアニメーション（子アニメーション）を部品として再生するパーツです。Player はインスタンスパーツごとに子の Context とスロットを持ち、毎フレーム `ss_instance_slot_step` で子を進めます。子をいつ始めるか、どのフレームを表示するか、ループや独立再生をどう扱うかは、スロットが決めます。Player は、子の用意・子の描画・子を持つホストの処理（通知など）を行います。

## 1. 子を用意する

アニメーションを読み込んだら、ssab のパーツからインスタンスパーツ（`PartTypeInstance`）をすべて探し、それぞれに次のものを用意します。

1. **参照先の ssab を探す。** `PartTypeInstance` の `ref_anime_pack`（`ref_anime_pack_hash`）が参照先の ssab、`ref_anime_name`（`ref_anime_name_hash`）がそのアニメーションです。参照先は、自分自身の ssab か、別の ssab です（[外部リソースとテクスチャ §4](../50_features/30_external_resources.ja.md#4-外部-ssab-の参照)）。
2. **子の Context を作る。** 参照先の ssab のリソースをバインドし、`ss_runtime_setup_animation_by_hash(child_ctx, ref_anime_name_hash)` で子アニメーションをセットアップします。ここではまだ再生しません。子はスロットが最初のキーに出会ったときに始めます（[§2](#2-スロットで子を進める)）。
3. **スロットを作る。** `ss_instance_slot_create()` で作ります。スロットはリソースを持たず、毎フレーム子の Context を受け取って動きます。

子もまた Player なので、子のアニメーションにインスタンスパーツやエフェクトパーツがあれば、子の中で同じ用意をします。

## 2. スロットで子を進める

```cpp
// 毎フレーム、親の update の後に、すべてのインスタンスパーツについて
for (InstanceChild& c : instance_children) {
    const ss_event_instance_info info = ss_runtime_get_active_event_instance(ctx, c.part_index);

    const ss_instance_step_result r = ss_instance_slot_step(
        c.slot, info, c.child_ctx,
        parent_frame_no,        // 親の再生ヘッド
        delta_seconds,          // 経過時間（秒）
        parent_looped);         // 親の ss_runtime_just_looped

    if (r.transitioned) {
        // スロットは新しいキーに合わせて子を設定した（区間・向き・ループ回数）。
        // 始めるのはホストの役目。play() で子をその区間の先頭へ飛ばす
        ss_runtime_play(c.child_ctx);
        reset_slots(*c.child);   // 子の中のスロットも初期状態に戻す（§6）
        c.child->on_started();   // 子の再生開始に伴うホストの処理（通知など）
    }
    c.visible = r.visible;
    c.frame_no = r.child_frame_no;   // 遷移したフレームも含めて
    c.looped = r.child_looped;
    c.speed = ss_instance_slot_get_speed(c.slot);   // 孫に渡す経過時間の倍率（§4）
}
```

`InstanceChild` は、インスタンスパーツごとに Player が持つ構造体（子の Context・スロット・子の Player）です。

**`ss_instance_slot_step` の経過時間は秒です。** `ss_runtime_update` がミリ秒なのと違うので、注意してください。

| 戻り値 | 意味 |
| :--- | :--- |
| `visible` | このフレームで子を描くか |
| `transitioned` | スロットが新しいキーに出会い、子をそれに合わせて設定した。**スロットは子を始めないので、子に `ss_runtime_play` を呼ぶ**。呼ばないと独立再生の子が進まない。**子の中のスロットも初期状態に戻す**（§6） |
| `child_frame_no` | 子の描画するフレーム番号。**小数を含む。丸めずに使う**（[再生制御 §6-2](../30_core/20_playback_control.ja.md#6-2-小数を捨てない)）。**`transitioned` のフレームでもこの値を使う。** スロットは子をすでに向きに応じた区間の先頭に置いており、`ss_runtime_play` が飛ばす先も同じフレームです。親のフレームに合わせる子（独立再生でない子）の値は親に追従しています。`play` の後に子のフレームを読み直すと、そうした子がそのフレームだけ区間の先頭に戻ります |
| `child_looped` | 独立再生の子が 1 周した（§4） |
| `independent` | 子が独立再生か |

**子の時計を `draw_order` で進めないでください。** 非表示のインスタンスパーツは `draw_order` に入らないので、`draw_order` を走査しながら `step` すると、非表示の間は独立再生の子の時計が止まり、表示に戻ったときに止まっていた分だけ遅れます。**すべてのインスタンスパーツを ssab から列挙し、パーツごとにスロットを持ち、毎フレーム漏れなく `step` してください。** `draw_order` と `visible` は、描くかどうかと描く順番を決めるためだけに使います。

## 3. 独立再生

インスタンスパーツとエフェクトパーツには、親の再生速度や停止にかかわらず、自分の経過時間で進む「独立再生」の設定があります（エフェクトパーツはフレームレートの上書きには従います。[エフェクトパーツ §2](./60_effect.ja.md#2-ss_effect_slot_step-の引数)）。独立再生かどうかは、`ss_instance_slot_is_independent` / `ss_effect_slot_is_independent` で分かります（インスタンスパーツは `ss_instance_slot_step` の戻り値の `independent` でも分かります）。

- **親が一時停止中でも、シークで親のフレームが動いていなくても、`step` を呼び続けてください。** 呼ばないと、パーティクルが空中で止まるなど、不自然な見た目になります。
- 独立再生を始めたりやり直したりできるのは、**明示的に置かれた再生のキー**（`EventInstance` / `EventEffect`）だけです。現在のフレームに明示的なキーが無い場合（アニメーションの先頭に置かなかった場合など）、Brain はフレーム 0 から始める暗黙のキーを使いますが、独立再生の子は、親がループしてもこの暗黙のキーではやり直しません。
- **同じキーをもう一度通っても、やり直しません。** スロットは最後に再生を始めたキーを覚えていて、親のループで同じキーに戻ってきても無視し、別のキーのときだけやり直します。そのため、独立再生・有限の長さ・明示的なキーが 1 つ、という構成は、親が何度ループしても **1 回だけ** 再生します（寿命で消えた後も同じ）。周期的に出したい場合は、独立再生を外して親のフレームに合わせるか、エフェクト側を無限ループにしてください。

これらの判定はすべてスロットの中で行われます。Player は、`step` の戻り値のとおりに動けば十分です。

独立再生の子は、親の逆再生とシークに追従しません（[制限事項 §3](../10_introduction/20_limitations.ja.md#3-独立再生のパーツは逆再生とシークに追従しない)）。

## 4. 子に渡すもの

子が自分のインスタンスパーツやエフェクトパーツを進めるとき（孫を進めるとき）、親から次のものを渡します。

| 値 | 渡し方 |
| :--- | :--- |
| 親の再生ヘッド | `r.child_frame_no` を、子にとっての親の再生ヘッドとして渡す |
| 親がループしたか | `r.child_looped` を渡す。独立再生の子は親の時間ではなく自分の経過時間で回るので、孫にとっての「親がループした」は、親アニメーションの `ss_runtime_just_looped` ではなくこの値。渡し忘れると、孫の再生のキーが子のループでやり直されず、2 周目から再生されない |
| 経過時間 | 親の経過時間に、`ss_instance_slot_step` の後に `ss_instance_slot_get_speed` で読んだ速度の絶対値を掛けた値。子はその速度で進むので、孫も同じ速度で進める。親と同じ値を渡すと、速度が 1 以外のキーで孫だけが違う速さで進む。`ss_event_instance_info` の `speed` は使わない。親が独立再生の子の最初の明示的なキーより前に戻ると、そこには暗黙のキーの 1 が入るが、スロットは暗黙のキーを無視して子を前のキーの速度で進め続けるので（§3）、孫だけが違う速さで進む。子自身の `ss_instance_slot_step` には親の経過時間をそのまま渡す（速度はスロットの中で掛かる） |
| サブフレームの設定 | 親と同じ設定を子に渡す。親の設定が変わったときも、子を作ったときも渡す。渡さないと、親は滑らかに動くのに子だけが整数のフレームで動く |
| マスクの設定 | 合成した設定を渡す（[マスク §2-6](./40_mask.ja.md#2-6-インスタンスを通したマスクの設定の合成)） |

## 5. 子を描く

`draw_order` の中でインスタンスパーツの位置に来た DrawBatch（`kind == Instance`）で、子を描きます。

- 子の FrameData は、子の Context で `ss_runtime_get_frame_data(child_ctx, frame)` を呼んで作ります。`frame` は `r.child_frame_no`（サブフレームを使わないなら切り捨てた値）です。
- 子のワールド行列は、子アニメーションの中での値です。**インスタンスパーツのワールド行列を、子全体の根元の変換として掛けてください。**
- **インスタンスパーツの不透明度（`PartState.alpha`）を、子全体に掛けてください。** 子は別の Context なので、Brain は親の不透明度を子に伝えません。**インスタンスパーツ自身のパーツカラーは、子に掛けないでください。** 子に伝えるのは不透明度だけです。
- `visible` が偽のとき、またはインスタンスパーツが非表示で DrawBatch に無いときは、子を描きません。
- パーツオーバーライドは子の中には届きません（[パーツオーバーライド §3-3](../50_features/20_part_overrides.ja.md#3-3-表示のオーバーライド)）。

## 6. 再生し直すとき

次の 2 つのときは、**スロットを `ss_instance_slot_reset` / `ss_effect_slot_reset` で初期状態に戻してください。**

- **親を `play` で先頭から再生し直すとき。** すべてのスロットを戻します。子の中のスロットも、再帰的に戻します。
- **スロットが子を始めたとき（`transitioned`）。** 子は区間の先頭からやり直すので、子の中のスロット（孫のインスタンスと子のエフェクト）を、再帰的に戻します。子を始めたスロット自身は戻しません。

スロットは最後に再生を始めたキーを覚えています（§3）。戻さないと、再生し直した最初のキーが「前回と同じキー」とみなされ、独立再生の子やエフェクトが始まりません。子を始めたときに戻さないと、子が区間の先頭からやり直しても、孫と子のエフェクトは前の続きのまま進み、子と一緒に始まりません。

```cpp
// Player の中のスロットを、子の中まで再帰的に戻す。
// reset_slots と Player / EffectChild は、Player が用意するものです
void reset_slots(Player& p) {
    for (EffectChild& e : p.effect_children) {
        ss_effect_slot_reset(e.slot);
    }
    for (InstanceChild& c : p.instance_children) {
        ss_instance_slot_reset(c.slot);
        reset_slots(*c.child);
    }
}
```

## 7. 子の終了とループ

**独立再生の子**は、スロットが子の Context を時間で進めるので、子の Context に通常の再生の API がそのまま使えます。

```cpp
if (ss_runtime_is_finished(c.child_ctx)) { /* 子が設定のループ回数を再生し終えた */ }
```

`ss_runtime_is_finished` は状態なので、[再生制御 §7](../30_core/20_playback_control.ja.md#7-ループと終了の検知) のとおり立ち上がりを取って通知してください。立ち上がりの検出に使う前回の値（再生制御 §7-1 の `prev_finished` にあたるもの）は、`r.transitioned` のときに戻してください。

**親のフレームに合わせる子（独立再生でない子）** は、毎フレーム親のフレームからシークされるだけで、再生の状態（`is_playing` やループの残り）を持ちません。そのため `ss_runtime_is_finished` は **常に偽** です。この子は、設定のループ回数を終えると **最終フレームで止まって表示されます。** 子の終了をきっかけに処理をしたい場合は、親アニメーションのキーで表してください。
