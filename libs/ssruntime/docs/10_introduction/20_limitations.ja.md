# 制限事項

Brain と ssab の技術的な制約のうち、Player の設計に影響するものの一覧です。実装に入る前に読んでください。各項目の詳しい説明と対処は、項目の末尾のリンク先にあります。

## 1. テキストとサウンドは Player が実装する

Brain はテキストの描画も音の再生も行いません。ssab に入っているデータと、描画順やタイミングだけを渡します。

| 機能 | Brain が渡すもの | Player が実装するもの |
| --- | --- | --- |
| テキスト | ssab の設定（`PartTypeText`）と、ビットマップフォントのグリフ表（`FontBitmap` / `FontGlyphBitmap`）。描画順の位置を示す、ジオメトリを持たない `DrawBatch` | 文字の配置、アウトラインフォントのラスタライズ、描画のすべて |
| サウンド | 再生の指示（サウンド名・再生回数・タイミング）を持つイベント | 音声の読み込みと再生 |

テキストについては、さらに次の制約があります。

- マスクとして作画されたテキストパーツ（`draw_as_mask`）は描画計画から除外され、何も描かれず、マスクとしても働きません。
- カーニングは ssab に入りません。
- ビットマップフォントのグリフは 16 bit の文字コードで引くため、U+FFFF を超える文字は扱えません。

→ [9 スライス・シェイプ・テキスト §3](../40_parts/30_special_parts.ja.md#3-テキスト) / [オーディオ](../50_features/50_audio.ja.md)

## 2. WebAssembly は SIMD 版と非 SIMD 版がある

Web 向けの標準のビルドは WebAssembly SIMD を使うため、SIMD に対応していない実行環境では読み込めません。そうした環境（RPG Maker MZ に同梱の NW.js など）向けに、SIMD を使わないビルド（`runtime-web-nosimd`）を配布しています。JavaScript 側のインタフェースは同じで、差し替えるのは `.wasm` だけです。

## 3. 独立再生のパーツは逆再生とシークに追従しない

独立再生（`independent=true`）のインスタンスパーツとエフェクトパーツは、親のフレームではなく自分の経過時間で進みます。自分の時計は巻き戻らず、親の任意のフレームでの累積時間も一意に決まらないため、親の逆再生とシークでは正しく描画されません。順方向のフレームスキップには追従します。

独立再生を含むアニメーションを逆再生・シークで使う場合は、その子が順方向の再生でしか正しく描画されないことを、Player の利用者に伝えてください。

→ [インスタンスパーツ §3](../40_parts/50_instance.ja.md#3-独立再生)

## 4. シークは途中のフレームのイベントを発火しない

`ss_runtime_set_frame_no` で再生位置を動かすと、移動元から移動先までの間にあるイベント（ユーザーデータ・シグナル・オーディオ）は発火しません。

→ [イベント §3](../30_core/30_events.ja.md#3-イベントが報告されるフレーム)

## 5. Brain は ssab を検証しない

Brain は、処理速度とバイナリサイズのために、入力の ssab の構造を検証しません。壊れた ssab や細工された ssab を渡すと、範囲外のメモリを読んでクラッシュすることがあります。ネットワークや利用者の入力から ssab を受け取る Player は、Brain に渡す前に検証してください。

→ [ロードと初期化 §2](../30_core/10_initialization.ja.md#2-ssab-を渡す前の検証)

## 6. borrow した ssab のバイト列は Player が保持し続ける

`ss_resource_create_borrow` で作ったリソースは、Player のメモリにある ssab のバイト列を直接参照します。リソース自身と、それを参照するすべての Context・エフェクトスロットを破棄するまで、そのバイト列を解放しないでください。

リソースと Context の破棄順は自由です。リソースは参照カウントで管理されており、Context がバインドしている間は `ss_resource_destroy` を呼んでも解放されません。

→ [ロードと初期化 §1](../30_core/10_initialization.ja.md#1-リソースと-context)

## 7. 埋め込みモードの ssab

アセットを ssab に埋め込むモードには、次の制約があります。

- アセットは `sspj` と `ss*e` ファイルに書かれたファイルパスをキーに格納されます。同じファイルパスが複数あるとキーが衝突するため、プロジェクト内のアセットのパスが重複しないようにしてください。
- 埋め込まれるのは、そのアニメーションが使うアセットだけです。外部インスタンスとして参照する別の ssab は埋め込まれないので、その ssab のファイルは別に用意してください。

→ [外部リソースとテクスチャ §4](../50_features/30_external_resources.ja.md#4-外部-ssab-の参照)

## 8. アニメーションミキシング

- 同じ ssab の中のアニメーションだけを重ねられます。
- セル・パーツカラー・非表示などの離散的なアトリビュートは track 0 の主アニメーションに従い、track 0 のクロスフェードが始まると入ってくる側のものに替わります。
- 尺の違うソースの位相は同期しません。
- パーツ単位のマスクはありません。トラックが影響する範囲は、そのアニメーションがキーを打っている範囲です。

→ [アニメーションミキシング §9](../50_features/10_animation_mixing.ja.md#9-制約)

## 9. オーディオは逆方向の再生中に鳴らせない

多くのオーディオ API は音声の逆再生に対応していないため、再生が逆方向に進んでいる間は音を鳴らさないでください。イベント自体は方向にかかわらず届きます。

→ [オーディオ §2](../50_features/50_audio.ja.md#2-再生する条件)
