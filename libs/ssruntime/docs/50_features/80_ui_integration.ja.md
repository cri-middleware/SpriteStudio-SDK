# UI 統合：当たり判定・UI 状態・reduced motion

アニメーションをボタンのような UI の部品として使うホストは、ポインタがどのパーツに当たったか、部品がどの状態にあるか、動きを減らす設定が有効かを、アニメーションの見た目に結びつける必要があります。これに Brain は関わりません。当たり判定は直前の tick が組み立てたフレームを読むだけ、状態はラベルの区間の再生、reduced motion は再生を止めるかどうかなので、Player の中で完結します。

UI のロジックは、使う人だけが払うアダプタに置いてください。ホストの UI 部品に依存する別のパッケージや別のモジュールです。アニメーションを再生するだけのアプリには、何も増やさないでください。Player の中核に足すのは、呼ばれたときだけ計算するもの（パーツの輪郭と `hitTestPart`、[ラベルによる再生区間](../20_design/30_api_conventions.ja.md#8-1-選択と再生を分ける)）だけです。

このページは、UI 統合を提供する Player がそろえるもの — 名前、既定値、意味 — をまとめたものです。ホストのボタン部品への載せ方（継承するか包むか、操作のコールバックの名前と時機）はホストが決めます。

## 1. 当たり判定

### 1-1. `hitTestPart`

| 項目 | 内容 |
|---|---|
| 引数 | 点と、対象パーツの集合（パーツ名かインデックス。省略できる） |
| 戻り値 | 点が当たったパーツのインデックス。当たらなければ、その Player の `findPartIndex` が見つからないときに返すもの（`-1`、`None` など） |
| 対象を省略したとき | 輪郭を持つすべてのパーツから探す |
| 重なっているとき | 描画順で一番手前のパーツ |

点は、Player がパーツの輪郭を返す空間で受け取ります。`partTransform` と同じ空間を推奨します。

パーツ 1 つを読むほかの API と同じく、**直前の tick が組み立てたフレームから答えてください**（[API 規約 §9](../20_design/30_api_conventions.ja.md#9-パーツの読み出し)）。判定のためにフレームを組み立てないでください。

FrameData の `draw_order` には非表示のパーツが入らない（マスクとして描く場合を除く）ので、`draw_order` を後ろから見て最初に当たったパーツが一番手前です。

```cpp
// partOutline() と contains() は §1-2 の輪郭を扱う Player の関数（C-API には無い）
int hitTestPart(const ss::FrameData* frame, Point point, const std::set<int>* targets) {
    auto order = frame->draw_order();
    for (int rank = int(order->size()) - 1; rank >= 0; --rank) {
        int p = order->Get(rank);
        int part = frame->parts()->Get(p)->part_index();
        if (targets && !targets->count(part)) continue;
        auto outline = partOutline(frame, p);
        if (outline && contains(*outline, point)) return part;
    }
    return -1;
}
```

### 1-2. パーツの輪郭

輪郭の形・型・座標系は、Player が UI ツールキットに合わせて決めます。ただし、どのパーツをどう囲むかは、次のとおりにそろえることを推奨します。回転した絵にも合うよう、輪郭は 4 点で返すことを推奨します。

| パーツ | 輪郭 |
|---|---|
| セルのあるパーツ | ローカル頂点（`ss_runtime_get_local_vertices`）の四隅にワールド行列と、Player が根元に加える変換（反転・オフセット）を掛けた 4 点。スキューと頂点変形を含む |
| メッシュパーツ | メッシュの頂点（`ss_runtime_get_mesh_vertices_x` / `_y`、ワールド座標）を囲む軸平行の矩形に、根元の変換を掛けたもの。スキンメッシュのパーツ自身の変換は根元の近くにあるので、四隅に行列を掛けても絵と合わない |
| セルが無くサイズのあるパーツ（シェイプ） | FrameData のパーツの `size_x/y` を `pivot_x/y` の周りに取った矩形（左 `-(0.5 + pivot_x) * size_x`、上 `-(0.5 + pivot_y) * size_y`）に、ワールド行列と根元の変換を掛けた 4 点 |
| ヌル・ボーン・インスタンス・エフェクトのパーツ | 輪郭なし（サイズが 0） |
| 非表示のパーツ | 輪郭なし。アルファ 0 で描いているパーツには輪郭がある |

シェイプの頂点変形でサイズの外へ出た角は、輪郭に入りません。シェイプの頂点バッファを読めば追えますが、どの Player もすでに読んでいるサイズとピボットだけで作れる形を選んでいます。頂点変形の無いシェイプでは、描いた頂点を囲む矩形と一致します。

### 1-3. 押せる範囲

アダプタがボタンとして押せる範囲は、**絞らなければ表示の箱全体**です。絞るときは対象パーツの輪郭の和で、対象を省略したら輪郭を持つすべてのパーツの和です。キーボードと読み上げからの操作は絞らないでください。

- **ホストのボタンが、子の答えに関係なく箱全体でポインタを受ける場合**（Flutter の `InkWell` など）は、子では絞れません。絞るものをボタンの外側に置き、点を中のビューの座標に写して `hitTestPart` に渡してください。ボタンのパディングがあってもずれません。
- **部品が自分で当たり判定を答えるホスト**（Flame の `containsLocalPoint`、PixiJS の `hitArea`）では、部品がパーツの輪郭で答えます。
- **描画が箱で切り取られる環境**では、押せる範囲も箱の中に限ってください。箱の外の部分は画面にありません。

## 2. UI 状態

### 2-1. 状態の語と優先順

状態の語は `normal` / `hover` / `pressed` / `disabled` / `focused` の 5 つです。ホストの状態からの写し方は Player が決めます（uGUI の Highlighted は `hover`、Godot の `DRAW_HOVER_PRESSED` は `pressed`、Ren'Py の insensitive は `disabled` など）。

同時に立ったときは、`disabled` > `pressed` > `hover` > `focused` > `normal` の順で 1 つを選んでください。

### 2-2. 状態の区間

既定では、状態と同じ名前のラベルを 1 つのアニメーションに置きます。ラベルは小文字で、完全一致で引きます。

- 状態の区間は、そのラベルのフレームから、**次のラベル**の 1 フレーム手前までです。次のラベルが無ければアニメーションの終わりまでです。区間はループ再生します。
- 次のラベルは、状態の名前に限らず、アニメーションのすべてのラベル（`reduced_motion` も、状態と関係ないラベルも）のうち、開始より後のフレームにある最初のものです。
- **ssab のラベルはフレーム順に並んでいません**（`AnimationData.labels` は名前のハッシュ順）。フレーム順に並べ直してから次のラベルを引いてください。
- 状態のラベルを読むアニメーションは、既定ではプレイヤーが選んでいるアニメーションです。

### 2-3. ラベルが無いとき

状態のラベルが無いときは、次の順に落としてください。

| 状態 | 落とし先 |
|---|---|
| `hover`、`focused`、`disabled` | `normal` |
| `pressed` | `hover`、それも無ければ `normal` |
| `normal` | アニメーション全体 |

### 2-4. コードからの上書き

状態ごとに、アニメーション名か、ラベルの区間を渡して既定を上書きできるようにしてください。

- 上書きは、その状態に落ちてくる状態にも効きます。`hover` を上書きすると、ラベルの無い `pressed` もその区間を再生します。
- パックに無いアニメーションやラベルを指す上書きは、1 度だけ報告し（[API 規約 §7](../20_design/30_api_conventions.ja.md#7-失敗の伝え方)）、その状態は上書きが無いものとして扱ってください。

状態の区間を、§2-3 の落とし先と上書きを含めて 1 つの関数で引くことを推奨します。reduced motion の判断（§3）も同じ関数で返すと、ランタイムも表示ノードも無しに、すべての分岐をテストできます。

### 2-5. 切り替え

- 状態か選択（§2-6）が変わったら、新しい区間の先頭から**すぐに**再生してください。再生途中の区間は捨てます。
- 区間・ループ回数（無限）・再生と停止は、**アダプタが握ります**。ホストは同じプレイヤーを並行して操作しないでください。
- 同じ状態を同じ選択・同じ reduced motion で示し直されたら、何もしないでください。ホストは状態を毎フレーム示してかまいません。パックを読み込み直したら、示し直してください。

パックの読み込み完了を知らせる口が無いホストでは、アダプタが毎 tick 状態を示し直し、同じ状態・同じパック・同じアニメーションなら何もしない形にします。状態はパックが入った次の tick に出ます。

### 2-6. 選択状態

ホストのボタン部品が選択（トグルのオン・オフ）を持つ Player では、選択状態を実装することを推奨します（Ren'Py の `selected_` の付くスタイル、Flutter の `WidgetState.selected`、uGUI の `Toggle.isOn` など）。持たないホスト（PixiJS の `@pixi/ui` の `ButtonContainer` など）では実装しません。

- 選択は、§2-1 の 5 つの状態と組み合わさる真偽値です（語幹 `selected`）。6 つ目の状態にはしません。選択中のボタンにも hover や無効があるからです。
- 選択中の区間は、状態の名前に `selected_` を付けたラベル（`selected_normal`、`selected_hover` など）から引きます。区間の終わりと並べ直しは §2-2 のとおりです。
- ラベルが無いときは、§2-3 の落とし先の列に `selected_` を付けたものを先に、付けないものを後に引いてください。選択中の `hover` は、`selected_hover`、`selected_normal`、`hover`、`normal`、アニメーション全体の順です。一時的な hover の反応より、オンとオフの区別を残します。
- §2-4 の上書きは、`selected_hover` などの名前でも渡せるようにしてください。

## 3. Reduced motion

入力は真偽値で受けてください（語幹 `reducedMotion`）。OS の設定（`prefers-reduced-motion`、`MediaQuery.disableAnimations` など）を読むのは任意です。ゲームのホストの多くは OS の設定を読めないからです。

真のときの振る舞いは次のとおりです。

- 今の状態の区間の先頭フレームで止めます。状態が変わったら、新しい区間の先頭フレームで止めます。
- アニメーションに `reduced_motion` ラベルがあれば、`normal`（と、`normal` に落ちてくる状態）だけは、代わりにその区間（次のラベルの 1 フレーム手前まで）をループ再生します。ほかの状態は止めたままにして、押下や無効の見た目を残します。選択中のラベル（§2-6）から引いた区間も止めたままにして、オンの見た目を残します。
- 止めている間は、ユーザーデータ・サウンドなどのイベントを出さないでください。`pause` ではなく `stop` で止めます。`reduced_motion` の区間を再生しているときは、その区間のイベントが普通に出ます。

## 4. 読み上げの既定

- 何も指定されなければ、**装飾として扱い、読み上げないでください**。
- アダプタは、画像の代替テキストに当たるラベルを受ける口を持ってください（Flutter の `semanticLabel`、PixiJS の `accessibleTitle` に渡すもの）。役割（button など）と操作は、ホストの部品が持ちます。

## 5. ホストごとの事情

- **操作のコールバックはそろえません。** 名前と時機はホストのボタン部品に合わせます。Flutter のボタンは離したときの `onPressed`、Flame の `ButtonComponent` は押したときの `onPressed` と `onReleased`・`onCancelled` です。この規約が決めるのは状態と区間だけです。
- **UI のフォーカスを持たないホスト**（ゲームエンジンなど）では、`focused` はゲームが立てる口にします。ゲームパッドやキーボードで動かすメニューが、選んでいるボタンに立てます。`disabled` と reduced motion も、同じくゲームが渡します。
- **アダプタが別のパッケージにあるとき**は、中核がアニメーションのラベル表を公開する口が要ります（§2-2 の区間を引くため）。
- **Godot の `toggle_mode` のボタン**では、`get_draw_mode()` がオンのトグルを `DRAW_PRESSED`（hover 中は `DRAW_HOVER_PRESSED`）で返します。このボタンでは、それを `pressed` に写さず、選択を `button_pressed` から読んでください。

## 6. この規約で決めないこと

- 状態を切り替えるときのクロスフェード。
- reduced motion をプレイヤーのプロパティにするか、アダプタだけに置くか。
