# 配置: fit と align

Player はアニメーションを、ホストが渡したターゲットへ作者が作った大きさのまま描きます。一方、UI のビューやサイズを持つノード、エディタのプレビューのように箱をレイアウトするホストは、アニメーションをその箱に収める必要があります。これに Brain は関わりません。箱とビューの大きさから求める計算だけなので、Player の移植可能な中核に置きます。そうすれば Player が公開するすべての API（C の API や JavaScript の API など）とエンジンのアダプタが同じものを受け継ぎ、レンダラー無しでテストできます。

このページは、配置を提供する Player が移植するもの — 名前、既定値、計算 — をまとめたものです。ホストの API にどう載せるか（prop、ノードのプロパティ、関数）はホストが決めます。

## 1. 配置の指定

| フィールド | 値 | 既定値 | 意味 |
|---|---|---|---|
| `fit` | `contain` / `cover` / `none` | `contain` | 箱をビューへどう拡大縮小するか。`none` は収めない指定で、スケール 1、原点はビューの中心。呼び出し側が `offset` と `scale` で置きます |
| `align` | `center`、`top`、`bottom`、`left`、`right`、`top-left`、`top-right`、`bottom-left`、`bottom-right` | `center` | 箱のどの点をビューの対応する点に合わせるか |
| `frame` | Player ローカル単位の箱 | 作者のキャンバス（[§2](#2-箱をどこから取るか)） | 収める箱 |
| `offset` | ピクセル | `(0, 0)` | 収めた後、求めた原点に足す量 |
| `scale` | 倍率 | `1` | fit で求めたスケールに掛ける倍率。置き換えはしません |
| `flipX`、`flipY` | 真偽値 | `false` | 反転。どちらの端に揃えるかが変わります |

`fit` の語は `<Image resizeMode>` のものです。UI のホストがすでに持っている語だからです。CSS の `object-fit` / `object-position` や Godot の `stretch_mode` のように独自の語彙を持つホストは、自分の API ではその綴りを使ってかまいません。ただし中身はこの 3 つの値です。回転は配置の指定に含めません。呼び出し側が持っている値をそのまま渡してください。

`align` は独立した 2 つの軸に分かれ、それぞれ `-1`、`0`、`1` をとります。**縦の軸では `-1` がビューの上端です** — 数学の向きではなく、画面の向きです。

## 2. 箱をどこから取るか

**呼び出し側が `frame` を渡さないとき、箱はアニメーションの作者のキャンバスです**。キャンバスの大きさを、ピボットで原点に対して置いたものです。コストは掛からず、再生中に動かず、作者が構図を決めた枠そのものです。キャンバスは再生中のアニメーション自身のもので、同じパックでも違うことがあります。`Ringo` では `dead` が 1300×600、`slipdown`・`slipdown_wait`・`wakeup` が 900×600、ほかは 800×600 です。パック全体で同じスケールにしたいホストは、最初の `setAnimation` の後にキャンバスを一度だけ読み、以後はそれを `frame` として渡します。

どちらも ssab のアニメーションにあります（`AnimationData` の `canvas_size` と `pivot`）。Brain はピボットを適用せず、ランタイムのアニメーションのメタデータにも含まれないので、両方とも ssab から読んでください。ピボットはキャンバスの中心からの正規化された位置で、エディタの空間（Y が上向き）で表されています。Y が下向きの Player ローカル空間では、箱は次のとおりです（原点が中心、単位がピクセルという既定のままの場合です。`ss_runtime_set_origin` で左上にするか `ss_runtime_set_unit` で正規化すると、Brain がルートのパーツをずらすか座標をキャンバスの大きさで割るので、式も変わります）。

```
x = -pivot.x * width - width / 2
y =  pivot.y * height - height / 2
```

`pivot (0, -0.5)` はキャンバスの下端で、地面に立つキャラクターはこう作られます。このとき箱は原点より上にすべて収まります。

Player は、描くジオメトリから箱を計測して `frameScope` として提供してもかまいません。`animation`（再生中の 1 つの箱）か `pack`（ファイル内の全アニメーションの和）で、明示的に選ぶものです。計測にはロード時に全フレームを評価する必要があります。`pack` はさらにキャラクターを小さく描きます。`Ringo` では `attack1` が Player ローカル単位で 383×527 なのに対し、パック全体の和はおよそ 1030×878 になります。`dead` がキャラクターを画面の大半ぶん右へ動かすからです。`pack` で得られる「アニメーションが変わってもスケールが変わらない」性質は、1 つのアニメーションのキャンバスを `frame` として渡せば計測せずに得られます。もっと詰めた箱が欲しい呼び出し側も `frame` を渡せます。**計測しない Player は `frameScope` を載せません**。中途半端に受け付けることはしません。

## 3. 計算

**スケール。** `sx = viewWidth / box.width`、`sy = viewHeight / box.height` とし、`contain` は `min(sx, sy)`、`cover` は `max(sx, sy)` をとります。その結果に `scale` を掛けます。

**反転は符号付きのスケールで表し、揃え方もそれに従います。** 描画は `p → origin + s · p` と写すので、`s` が負だと箱のどちらの端が低い側になるかが入れ替わります。各軸は符号付きのスケールで解いてください。反転せずに解いてから鏡映することはしません。

**各軸**は、その軸のビューの大きさ、符号付きのスケール `s`、箱の低い側の端 `lo` と長さ `size`、揃える側（`-1`、`0`、`1`）から次のように求めます。

| 側 | 原点 |
|---|---|
| `0`（中央） | `viewSize / 2 - s · (lo + size / 2)`。`s` の符号で変わらないので、安全な既定値です |
| `-1`（低い側） | `-s · lowEdge` |
| `1`（高い側） | `viewSize - s · highEdge` |

`lowEdge` は `s > 0` なら `lo`、`s < 0` なら `lo + size` で、`highEdge` はもう一方です。

**最後に `offset` を足します。** ほかのすべての後です。

**退化した場合はエラーにしません。** 大きさ 0 の箱や箱が無い場合、大きさ 0 のビューでは、割る数がありません。収めるのを飛ばし、`fit: none` と同じ収めない配置を返します。スケールは呼び出し側の `scale`、原点はビューの中心です。潰れた箱をレイアウトしたホストは、箱が大きさを持った時点でアニメーションが戻ります。

## 4. 座標

求めた原点は**ビューの座標**で、`(0, 0)` がビューの左上、Y は下向きです。したがって収めないときの原点はビューの中心で、`(0, 0)` ではありません。Player 自身の配置の呼び出しが別の点（たとえばビューの中心）から測る場合は、渡すときに変換してください。ここを誤ると、正しく収まった絵がビューの半分ずれて見えます。
