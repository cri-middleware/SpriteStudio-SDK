# 外部リソースとテクスチャ

テクスチャの差し替え（作画で指定されたものと、実行時にプログラムから行うもの）と、別の ssab のアニメーションを参照するインスタンスパーツの扱い方です。テクスチャの読み込みそのものは [ロードと初期化 §3](../30_core/10_initialization.ja.md#3-テクスチャの読み込み) にあります。

## 1. テクスチャのキー

描画でバインドするテクスチャは、常に `DrawBatch.texture_hash` で決まり、その値はセルマップ名のハッシュか、テクスチャのファイル名のハッシュです（[ロードと初期化 §3](../30_core/10_initialization.ja.md#3-テクスチャの読み込み)）。

**セルマップ名には拡張子が付きません。** `common.ssce` のセルマップ名は `common` で、そのハッシュは `fnv1a("common")` です。一方、テクスチャ変更（`TCHG`）が指すのはテクスチャのファイル名（`common.png` など）なので、`fnv1a("common.png")` です。文字列が違うので、2 つはまったく別の値です。**Player のテクスチャのマップは、両方をキーとして持つ必要があります。** `cellmaps()` と `external_textures()` の両方を読み込めば、`texture_hash` は必ず見つかります。`TCHG` が指すすべてのテクスチャ名が `external_textures()` に入っていることは、コンバータが保証しています。

**テクスチャのハッシュは、1 つの ssab の中でしか一意ではありません。** セルマップのハッシュも外部テクスチャのハッシュも名前だけから作られ、どの ssab に属するかを含みません。そのため、別々の ssab が同じハッシュで別の画像を指すことがあります（どちらにも `common` というセルマップがある、など）。複数の ssab を読み込む Player は、テクスチャのマップを ssab ごとに持つか、キーを ssab とハッシュの組にしてください。DrawBatch を描くときは、その Context にバインドした ssab のマップを引きます。

## 2. 作画で指定されたテクスチャ変更

SpriteStudio のアトリビュート「テクスチャ変更」（`TCHG`）は、パーツが参照する **セルはそのままに、読むテクスチャだけを差し替える** 機能です。同じ配置で色や衣装の違うテクスチャを用意しておき、タイムラインで切り替える用途に使います。

### 2-1. Player がすることは無い

Brain はこのアトリビュートを計算し、その値を **DrawBatch の区切りの条件に含めます。** そのため、

- テクスチャ変更が効いているパーツは、同じセルマップを参照する他のパーツと **同じ DrawBatch になりません**（別の DrawBatch に分かれます）。
- 各 DrawBatch の `texture_hash` は、その DrawBatch が実際にバインドすべきテクスチャを指します。

つまり、**`texture_hash` をキーにテクスチャをバインドするいつもの描画ループのままで、テクスチャ変更は正しく描かれます。** パーツごとに状態を読んで DrawBatch を切り直す必要はありません。必要なのは、`external_textures()` を読み込んでおくことだけです（§1）。

### 2-2. 仕様

| 項目 | 挙動 |
|---|---|
| 補間 | **しない（ステップ）。** キーのフレームで切り替わり、次のキーまで保たれる |
| 空のテクスチャ名 | 作画の「差し替えない」。ssab には `0` で入り、パーツは自分のセルのテクスチャを使う（実際のテクスチャのハッシュとは衝突しない） |
| 効くパーツ | **セルを持つパーツ**（通常 / 9 スライス / メッシュ / マスク）。セルを持たないパーツ（シェイプ / テキスト / インスタンス / エフェクト）は `texture_hash == 0` のまま |
| セルの切り出し範囲・UV | **変わらない。** `ss_runtime_get_local_uvs` / `ss_runtime_get_cell_meta` は、元のセルマップのピクセル座標の値を返す |

> [!IMPORTANT]
> **差し替え先のテクスチャの大きさ**: Brain が返す UV とセルの範囲は、元のセルマップのピクセル座標のままです。Player はふつう、これを「バインドしたテクスチャの大きさで割って」正規化します。そのため、**差し替え先が元のセルマップと違う解像度だと、同じピクセルの範囲が、絵としては別の領域** を読むことになります。テクスチャ変更は、同じ大きさ・同じ配置のテクスチャに差し替える使い方を前提にしています。

### 2-3. `PartState.texture`

FrameData の `parts[].texture` にも、同じ値（テクスチャ名のハッシュ、差し替えが無ければ `0`）が入っています。`update_flag` の `AttributeTexture` が立っているときだけ有効です。

DrawBatch で描く Player は、これを読む必要はありません。パーツごとにエンジンのノードを作る `SceneGraph` モードの Player のように、DrawBatch を使わない実装だけが参照してください。

### 2-4. 注意

- **DrawBatch の数はフレームごとに変わります。** テクスチャ変更のキーが切り替わるたびに区切り方が変わるので、「DrawBatch の数は一定」という前提の最適化（バッファの使い回しなど）は成り立ちません。
- **`external_textures()` は「作画者が登録した外部テクスチャ」の一覧ではありません。** `TCHG` が指すテクスチャ名（`common.png` のように、セルマップ自身の画像を含む）も、ハッシュから名前を引けるようにコンバータが加えています。この一覧を「差し替えられるテクスチャ」として UI に出している Player では、出る項目が増えます（どれも差し替えの対象として正しいものです）。

### 2-5. 確かめ方

`tests/overall/TextureChange.ssae` を使います。2 つのパーツ（`TO_TEXTURE` / `TO_CELLMAP`）が同じ `common` セルマップを参照し、フレーム 1 でそれぞれ別のテクスチャに切り替わります。エディタと同じ絵になり、そのフレームで **DrawBatch が 2 つに分かれている** ことを確かめてください。

## 3. 実行時のテクスチャの差し替え

作画ではなく **プログラムから** 実行時にテクスチャを差し替える機能（衣装替え、表情の差分など）は、Player が実装します。[パーツオーバーライド](./20_part_overrides.ja.md) には含まれません。

1. 初期化のときに、ssab の定義どおりにテクスチャを読み込み、`texture_hash` をキーとするマップに入れる（§1）。
2. 差し替えるときは、そのキーのテクスチャを、別のテクスチャで上書きする。
3. 差し替えを解除するときは、ssab に書かれた元のパス（`cellmaps()` の `image_path`、または `external_textures()` の `name`）から読み込み直して、マップを元に戻す。
4. 描画では、いつもどおり `DrawBatch.texture_hash` でマップを引く。元のデータを変えずに、衣装替えや表情の変更ができる。

```cpp
void Player::set_cellmap_texture(const std::string& cellmap_name, Texture* override_texture) {
    uint32_t key = ss_runtime_hash_string(cellmap_name.c_str());

    if (override_texture != nullptr) {
        textures[key] = override_texture;                       // 差し替える
        return;
    }
    // 解除する: ssab の定義から元のテクスチャを読み込み直す
    auto cellmaps = ssab->cellmaps();
    for (uint32_t i = 0; i < cellmaps->size(); i++) {
        auto cellmap = cellmaps->Get(i);
        if (cellmap->name_hash() == key) {
            textures[key] = load_texture(resolve_path(cellmap->image_path()->c_str()));
            return;
        }
    }
    // 見つからなければ external_textures() も同じように探す
}
```

`load_texture` / `resolve_path` は、エンジンのテクスチャの読み込みとパスの解決を表す、実在しない関数です。

テクスチャ変更（`TCHG`）が効いているパーツは、そのフレームだけ別のハッシュでバインドされます。差し替えたキーがそのハッシュでなければ、差し替えは効きません（作画の指定が優先されます）。

上の手順と例は、テクスチャのマップがその Player だけのもので、1 つの ssab から作られている場合の形です。

**複数の Player で共有するテクスチャの表（デバイスやエンジン全体で 1 つの表）を使う Player は、キーのテクスチャを上書きしないでください。** 上書きすると、同じ ssab を再生しているすべての Player でテクスチャが替わります。代わりに、Player ごとに置き換えの表を持ち、差し替えるハッシュを、ほかのどのテクスチャのキーとも重ならないその Player 専用のキーへ向けてください。差し替え先のテクスチャは、共有の表にそのキーで登録します。描画では、テクスチャのハッシュをまず置き換えの表で引き、載っていなければハッシュのまま共有の表を引きます。`DrawBatch.texture_hash` だけでなく、エフェクトやマスクの切り抜きが読むハッシュも同じ表に通してください。解除は、置き換えの表でそのハッシュを元のキーに向け直すだけです。共有の表の元のテクスチャには触れていないので、読み込み直す必要はありません。

置き換えの表も ssab ごとに持ってください（§1）。別の ssab から作られたインスタンスパーツの子は、その ssab の表で引くので、親の ssab に設定した差し替えは子に届きません。子にも効かせるには、子の ssab の表にも差し替えを設定してください。

## 4. 外部 ssab の参照

インスタンスパーツは、別の ssab のアニメーションを参照できます（[インスタンスパーツ §1](../40_parts/50_instance.ja.md#1-子を用意する)）。

1. 親の ssab の `external_instances()` を走査し、参照している ssab の名前（`anime_pack_name`）を集める。
2. それぞれ、**親の ssab と同じディレクトリの `<anime_pack_name>.ssab`** を読み込み、リソースを作る。読み込んだ ssab は、`SsAnimeBinary.name_hash`（ssab の名前のハッシュ）で引けるようにしておく。
3. インスタンスパーツの子を用意するとき、`PartTypeInstance.ref_anime_pack_hash` で読み込んだ ssab を引き、その中に `ref_anime_name_hash` のアニメーションがあれば、その ssab のリソースを子の Context にバインドする。見つからなければ、親の ssab 自身から探す。

埋め込みモードの ssab でも、参照先の ssab は埋め込まれていません（[制限事項 §7](../10_introduction/20_limitations.ja.md#7-埋め込みモードの-ssab)）。参照先の ssab のファイルを一緒に配置してください。
