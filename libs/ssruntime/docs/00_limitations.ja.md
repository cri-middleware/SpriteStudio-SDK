## 描画・再生機能のサポート範囲

ssruntime は **アニメーションの状態計算** を担う層であり、以下の機能の **実体は提供しません**。情報取得用 API のみ提供されるため、Player 側でホストエンジンと連携した実装が必要です。

| 機能 | ssruntime が提供するもの | Player 側で実装が必要なもの |
| --- | --- | --- |
| **テキスト描画** | グリフのレイアウト情報 (ビットマップ位置・サイズ・テクスチャ参照) | グリフのレンダリング |
| **サウンド再生** | 再生指示イベント (ファイル名・発火タイミング) | 実際の音声再生 (エンジンのオーディオシステム連携) |

> 関連章: [6. 再生制御とイベント処理](./06_playback_control.ja.md) / [10. 外部リソースとオプション機能](./10_optional_features.ja.md)

## WebAssembly (WASM) 環境

ssruntime の WASM ビルドは **WebAssembly SIMD 命令** を利用しています。

- **SIMD をサポートしていないブラウザでは動作しません**。
- 配信先のブラウザ要件として、WebAssembly SIMD への対応を前提としてください。

## `independent=true` パーツの逆再生 / シーク

インスタンスパーツ・エフェクトパーツの `independent=true` 設定は、**逆再生およびシーク操作では正しく動作しません**。

- `independent=true` の子は、親の timeline から切り離されてリアルタイム時計 (`delta_time`) で進行する仕様です。
- 親の **逆再生** (子の時計は単調増加で過去方向に戻れない) と、親の **シーク** (任意の過去フレームでの「子の累積時間」が一意に決まらない) で破綻します。
- 親の **順方向のフレームスキップ** には対応可能です。

**推奨運用**: SS7 のアニメ制作時には `independent=true` を使わない構成にしてください。やむを得ず使用する場合は、対応する子インスタンスが「順方向再生時のみ正しく描画される」ことを Player の利用者へ明示してください。

> 関連章: [8. 高度な機能と描画ループの拡張 §1 インスタンス再生](./08_advanced_rendering.ja.md)

## シーク (`set_frame_no`) はスキップしたフレーム上のイベントを発火しない

`ss_runtime_set_frame_no` で再生位置を直接ジャンプさせた場合、現在フレームから移動先フレームまでの **間にあるフレームのイベント (UserData / Signal / Audio) は発火されません**。次の `update()` ではシーク先フレーム 1 枚分のイベントのみが収集されます。

中間イベントも漏れなく扱いたい場合は、Player 側で移動量に応じて `update(delta)` を複数回呼ぶ、もしくはシーク区間のイベントを ssab から直接スキャンして発火する等のラッパー実装が必要になります。

> 関連章: [6. 再生制御とイベント処理](./06_playback_control.ja.md)

## ファイル参照 / リソース解決

ssab に格納されるファイル参照文字列 (テクスチャ・サウンド・フォントなど) の構成ルールは制限事項ではなく仕様です。Player 実装上の前提として **[5. データのロードと初期化 §3.0 ssab に格納されるファイル参照文字列の仕様](./05_initialization.ja.md#30-ssab-に格納されるファイル参照文字列の仕様)** を参照してください。

## 入力データのバリデーション非実施 (セキュリティ注意事項)

パフォーマンス最大化およびバイナリサイズの最小化(特に組み込み / WebAssembly 向け)を目的として、ssruntime は入力 `.ssab` データの構造検証(バリデーション)を **行いません**。

- 悪意を持って細工されたデータや破損した `.ssab` をロードした場合、範囲外メモリアクセス等による未定義動作やクラッシュを引き起こす危険があります。
- **対策**: ネットワーク経由やユーザー入力からの動的ロードを行う環境では、Player 側で事前にデータの整合性を検証するか、信頼できる安全なアセットのみをロードする設計にしてください。

## AnimationResource と Context のライフタイム

メモリ効率を最適化するため、1 つのアニメーションリソース (`AnimationResource`) を複数の再生コンテキスト (`Context`) で **共有** する設計になっています。

- `ss_runtime_bind_resource` でリソースを Context に紐付けた後、**Context が破棄されるか別リソースがバインドされる前に、元のリソースを破棄しない** でください。
- 違反するとダングリングポインタ (Use-after-free) が発生し、クラッシュの原因となります。

## ssab embedded モードの制限事項

ssab を **embedded モード** (アセットを ssab 自身に埋め込んで生成するモード) で利用する場合、以下の制限があります。

### 1. Assets ファイルパスのキー競合

ssab embedded は、`sspj` および `ss*e` ファイルに記載されている **Assets ファイルパスをキー** として利用します。

- 同じファイルパス名が複数存在すると **キー競合** が発生します。
- embedded を利用する際は、プロジェクト内のアセットファイルパスが **重複しない** ようにプロジェクトを構成してください。

### 2. 利用するアセットのみを埋め込む (外部インスタンス本体は含まない)

ssab embedded は、そのアニメーションパックが **実際に利用するアセットのみ** を埋め込みます。外部インスタンスとして参照される別の ssab ファイルの本体は埋め込まれないため、**外部インスタンスを利用する場合は参照先の ssab ファイルの実体を別途用意する必要** があります。

## アニメーションブレンド時の制限

`ss_runtime_add_blend_source` 等で複数アニメーションを合成する際の制約です (Phase 3 API)。

- **同一 SSAB 内のみブレンド可**: 複数 `AnimationResource` をまたぐ合成はサポート対象外。
- **Cell の一貫性が前提**: ブレンドする全アニメーションは「同一 part に同一 Cell を割り当てている」必要があります。`cell_meta_per_part` は primary から取られるため、Cell が異なるとサイズ・pivot ミスマッチで pose が崩れます。同一 SSAE 内のアニメーションでは通常問題になりません。
- **`parts_color` の α 二重定義**: `parts_color` を持つ part の視覚 α は primary 由来 (mix された `state.alpha` ではない)。`parts_color` を持たない part は mixed `state.alpha` が反映されるため、α ブレンド自体は機能します。
- **events 発火元は primary 固定**: 全 source の controller が進行しますが、`get_passed_event_indices` で取得できるイベントは primary のもののみ。
- **deform table の FrameData 浪費**: secondary source の deform は FlatBuffer に書き込まれるが unreferenced。FrameData サイズが膨らみますが正確性には影響しません。
