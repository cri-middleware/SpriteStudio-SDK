# 実装ロードマップ：overall.sspj による機能検証

Player の実装において、最も重要かつ確実な検証方法は **「SpriteStudio 7 本体のエディタ上での表示・動作と、自身の実装した Player の動作を常に比較すること」** です。

機能の段階的な検証には、本 SDK に付属しているテストプロジェクト **`tests/overall/overall.sspj` の利用を強く推奨します**。このプロジェクトには機能ごとのアニメーションが網羅されており、以下のステップに沿って確認していくことで、Player の機能を確実に完成させることができます。

## ステップ 1：基本描画の完成 (Basic)
まずはこのアニメーションが正しく表示されることを目指します。

- **確認対象**: `Basic.ssae`
- **チェックポイント**:
    - **位置・回転・拡大縮小**: 親パーツの動きに合わせて、子パーツが正しく追従しているか。
    - **不透明度 (Alpha)**: 親パーツの不透明度を下げたとき、子パーツも連動して薄くなっているか。

## ステップ 2：合成と色の反映 (BlendMode / PartsColor)
- **確認対象**: `BlendMode.ssae`, `PartsColor.ssae`
- **チェックポイント**:
    - **BlendMode**: 加算（Add）や乗算（Mul）が背景に対して正しく反映されているか。
    - **PartsColor**: パーツ全体または頂点ごとの着色が正しく行われているか。

## ステップ 3：高度な構造と変形 (Instance / Mask / Mesh)
SDK の **Slot API** と **SoA バッファ** を使用することで、これらを標準機能として実装できます。

- **確認対象**: `Instance.ssae`, `Mask.ssae`, `Mesh.ssae`
- **チェックポイント**:
    - **Instance**: メインのアニメーションの中で、別のアニメーションがループ再生されているか（Slot API による同期）。
    - **Mask**: マスク範囲内だけパーツが表示されているか（バッチ描画契約の適用）。
    - **Mesh**: 頂点変形やボーン追従（スキニング）が滑らかに行われているか（SoA バッファの利用）。

## ステップ 4：インタラクティブ機能 (UserData / Signal / Bounding)
ゲーム連携に不可欠な機能を確認します。

- **確認対象**: `UserData.ssae`, `Signal.ssae`, `Bounding.ssae`
- **チェックポイント**:
    - **UserData / Signal**: 特定のフレームでイベントが発火し、プログラム側で検知できているか。
    - **Bounding**: 当たり判定用の枠がパーツの動きに合わせて追従しているか。

## ステップ 5：視覚効果 (Effect)
パーティクル演出の最終確認です。

- **確認対象**: `Effect.ssae`
- **チェックポイント**:
    - **Effect**: 火花や煙などのパーティクルが飛び散り、時間とともに消えていくか（Effect Slot によるシミュレーション）。

---

## ステップ 6：Optional な機能の検証
必要に応じて、以下の特殊なパーツを確認します。
- **Sound**: 指定フレームで音が鳴るか。
- **9Slice**: 拡大時にコーナーが維持されているか。

---

## 🚀 将来の拡張予定 (Future Plans)
SDK の進化に合わせて、以下の機能が順次サポートされる予定です。
- **Text パーツ**: 動的なテキストレンダリングとレイアウト。
- **拡張シェーダー**: 標準以外のカスタムポストプロセスの統合。
- **パーツカラーの SoA 取得**: 現在パーツカラーは `FrameData.parts_color` テーブルから取得しますが、将来的に頂点データと並ぶ SoA バッファからの取得にも対応予定です。
