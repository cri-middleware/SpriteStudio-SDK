# 事前確認
libssruntime は Rust で実装されており、libssruntime から受け取るデータフォーマットには FlatBuffers を採用しています。以下の確認をお願いします。

# Rust のビルドサポート
Player を実装する対象のゲームエンジンがサポートする CPU アーキテクチャ、プラットフォーム を把握し、Rust がビルドに対応しているかを確認してください。

https://doc.rust-lang.org/beta/rustc/platform-support.html

libssruntime のリリース成果物に対象の CPU アーキテクチャ / プラットフォーム のライブラリバイナリが含まれていない場合は自前でのビルドをお願いします。

# プログラミング言語のネイティブラリブラリのバインディング
Player を実装する対象のゲームエンジンとプログラミング言語について確認してください。

- ゲームエンジンがネイティブライブラリ or wasm を取り込めるかを確認してください。
- プログラミング言語から C/C++ ライブラリ(or wasm ライブラリ)の関数をバインディングして実行できるかを確認してください。

# FlatBuffers のサポート
Player を実装する対象ゲームエンジンのプログラミング言語を把握し、FlatBuffers の flatc コマンドがその言語に対応しているかを確認してください。

https://flatbuffers.dev/support/

# Player 実装前段階

Player の実装を開始する前に、必要なツールの準備とプロジェクトのセットアップを行います。

# Player 用プロジェクトの用意
- **空プロジェクトの作成**: 対象のゲームエンジンや言語で、ビルドが可能な空のプロジェクトを用意します。
- **FlatBuffers の準備**: 
    - `flatc` コマンドを入手します。
    - SDK が提供する各 `.fbs` スキーマファイル（`libs/ssab/fbs/` および `libs/ssruntime/fbs/` ディレクトリ配下）から、Player で使用する言語のパースコードを生成します。
    - 生成されたコードと、FlatBuffers のランタイムライブラリ（`flatbuffers.h` 等）をプロジェクトに取り込みます。

```bash
# C++ の場合の生成例
flatc --cpp -o ./src/gen/ libs/ssab/fbs/*.fbs
flatc --cpp -o ./src/gen/ libs/ssruntime/fbs/*.fbs
```

- **libssruntime のリンク**: 
    - `libssruntime` をビルドし、生成された静的ライブラリ（`.lib` / `.a`）または動的ライブラリ（`.dll` / `.so` / `.dylib`）をプロジェクトに配置します。
    - リンカ設定を行い、ライブラリを成果物にリンクします。
    - `ssruntime.h` ヘッダーファイルをインクルードパスに追加します。

# ssab ファイルの用意
- **コンバートツールの入手**: `ssconverter-cli` を用意します。
- **テストデータの用意**: `tests/overall/overall.sspj` などをコンバートし、`.ssab` ファイルを作成します。
- **アセット登録**: 作成した `.ssab` を Player プロジェクトのアセットディレクトリに登録します。

# エンジン独自のアセット管理への組み込み（推奨）
多くのゲームエンジン（Unity, Godot, Unreal Engine 等）には、独自のリソース管理システムがあります。

- **カスタムインポーター/ローダーの実装**: 
    - エンジンが `.ssab` 拡張子を認識し、バイナリデータとして自動的に読み込めるようにします。
    - 例：Godot での `ResourceFormatLoader` の実装。
    - これにより、エディタ上でアセットをドラッグ＆ドロップで割り当てることが可能になり、ユーザビリティが大幅に向上します。

- **ベースディレクトリの保持**: 
    - `Reference` 方式（テクスチャ外部参照）を利用する場合、`.ssab` ファイルが存在するディレクトリのパスを Player に渡せるようにしておくと、テクスチャのロードパス解決が容易になります。

# 座標系の設定と「二重反転」の罠
移植先エンジンの座標系（Unity は Y-Up、Godot は Y-Down など）に合わせて、`ss_runtime_set_coordinate_system` で正しいフラグ（Y-Up=`0`, Y-Down=`1`）を設定する必要があります。
この際、ローカル空間の頂点計算ですでに上下反転が適用されていることを意識せず、ワールド行列側の計算でも自前で Y 軸を反転してしまうと、「二重反転（ダブルミラー）」が発生して表示がおかしくなります。エンジン仕様と提供データの仕様を合わせ、変換が二重にかからないよう注意してください。

# 動作確認：ビルドが通ること
この段階で、`ss_runtime_create()` などの API が呼び出せ、エラーなくビルド・実行ができることを確認してください。
