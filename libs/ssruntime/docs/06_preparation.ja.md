# Player 実装前段階

Player の実装を開始する前に、必要なツールの準備とプロジェクトのセットアップを行います。

# Player 用プロジェクトの用意
- **空プロジェクトの作成**: 対象のゲームエンジンや言語で、ビルドが可能な空のプロジェクトを用意します。
- **FlatBuffers の準備**: 
    - `flatc` コマンドを入手します。
    - `libs/ssruntime/fbs/` にある `ssab.fbs` から、Player で使用する言語のパースコードを生成します。
    - 生成されたコードと、FlatBuffers のランタイムライブラリ（`flatbuffers.h` 等）をプロジェクトに取り込みます。

```bash
# C++ の場合の生成例
flatc --cpp -o ./src/gen/ libs/ssruntime/fbs/ssab.fbs
```

- **libssruntime のリンク**: 
    - `libssruntime` をビルドし、生成された静的ライブラリ（`.lib` / `.a`）または動的ライブラリ（`.dll` / `.so` / `.dylib`）をプロジェクトに配置します。
    - リンカ設定を行い、ライブラリを成果物にリンクします。
    - `ssruntime.h` ヘッダーファイルをインクルードパスに追加します。

# ssab ファイルの用意
- **コンバートツールの入手**: `ssconverter-cli` を用意します。
- **テストデータの用意**: `tests/overall/overall.sspj` などをコンバートし、`.ssab` ファイルを作成します。
- **アセット登録**: 作成した `.ssab` を Player プロジェクトのアセットディレクトリに登録します。

# エンジン独自のアセット管理への組み込み（推奨）
多くのゲームエンジン（Unity, Godot, Unreal Engine 等）には、独自のリソース管理システムがあります。

- **カスタムインポーター/ローダーの実装**: 
    - エンジンが `.ssab` 拡張子を認識し、バイナリデータとして自動的に読み込めるようにします。
    - 例：Godot での `ResourceFormatLoader` の実装。
    - これにより、エディタ上でアセットをドラッグ＆ドロップで割り当てることが可能になり、ユーザビリティが大幅に向上します。

- **ベースディレクトリの保持**: 
    - `Reference` 方式（テクスチャ外部参照）を利用する場合、`.ssab` ファイルが存在するディレクトリのパスを Player に渡せるようにしておくと、テクスチャのロードパス解決が容易になります。

# 動作確認：ビルドが通ること
この段階で、`ss_runtime_create()` などの API が呼び出せ、エラーなくビルド・実行ができることを確認してください。
