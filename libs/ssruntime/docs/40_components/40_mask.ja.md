# Mask の実装

SpriteStudio 7 の「マスク」「クリッピングマスク」機能の実装ガイドです。両者はステンシルという同じ仕組みで実現されますが、**機能としては別物** です。本書は機能の定義を一次情報とし、実装パターンはそれに従属するものとして扱います。

---

## 1. 概念とパーツの役割

### 1-0. 用語

混乱しやすいフィールド名・用語を先に整理します。詳細は各節を参照してください。

| 用語 / フィールド | 読み出し元 | 意味 |
|---|---|---|
| **マスク（パーツ）** `PartTypeMask` | PartData（静的） | マスク専用のパーツ種別。常に pure マスク（色を描かない） |
| **マスク（機能）** | — | 自分より描画優先度が **低い** パーツを、形状の **外側** に残す |
| **クリッピング（機能）** | — | 自分より描画優先度が **高い** パーツを、形状の **内側** に収める |
| **writer** | — | ステンシルに書き込むパーツ（pure マスク または クリッピング） |
| **対象 (target)** | — | マスク／クリッピングの影響を受ける描画パーツ |
| **pure マスク** | — | 色を描かず穴になる writer（マスクパーツ＋マスク化された描画パーツ） |
| `Priority` | **FrameData（毎フレーム）** | 描画優先度。同着はパーツ ID で決まる（[§2-1](#2-1-スコープどの描画パーツにマスクが及ぶか)） |
| `mask` (float, `0..255`) | **FrameData（毎フレーム）** | カットアウト閾値を兼ねる。`0` で writer 無効（[§2-2](#2-2-マスクの効果のオプトアウト) / [§2-5](#2-5-カットアウト閾値被覆に書く画素の範囲)） |
| `mask_influence` | **PartData（静的）** | **役割で意味が変わる**（[§1-2](#1-2-パーツの役割と-mask_influence)）。OP または マスク対象フラグ |
| `mask_write` | **PartData（静的）** | 描画パーツを **クリッピング** writer にするフラグ |
| `draw_as_mask` | **PartData（静的）** | 描画パーツ (Shape/Text/Nines) を **pure マスク** 化する統合フラグ。オーサリングでは種別ごとの設定だが ssab では1つに集約 |
| `visible_inside_mask` | **PartData（静的）** | 極性。`1` = 内側に描画 / `0` = 外側に描画（[§2-4](#2-4-極性マスクの内側か外側のどちらに描画するか)） |
| `Hide` | **FrameData（毎フレーム）** | 非表示。※ Player では通常チェック不要（[§2-2](#2-2-マスクの効果のオプトアウト) 補足） |

> **【重要】読み出し元の区別**: マスク関連フィールドは 2 つの異なるテーブルに分かれています。実装時はどちらから読むかを必ず意識してください。
> - **PartData（静的・パーツ単位）**: `mask_influence` / `mask_write` / `visible_inside_mask` / `draw_as_mask` / パーツ種別。**1 回読めば以後フレームで不変**。
> - **FrameData（毎フレーム・アニメート）**: `mask` (float) / `Priority` (float) / `Hide` / `part_color` / `alpha`。**毎フレーム読み直す**。
>
> 以降の擬似コードでは出所を `part.data.*`（PartData）と `part.frame.*`（FrameData）で区別します。

### 1-1. マスクとクリッピングは別機能

用途は似ており実装も同じ仕組みですが、機能としては別物です。

| | **マスク** | **クリッピング** |
|---|---|---|
| 機能するパーツ種別 | **「マスク」パーツ** | 描画パーツ（通常 / メッシュ / シェイプ等） |
| 自分の色描画 | **しない**（pure。穴になる） | **する**（自分を描画しつつステンシルにも書く） |
| 適用先 | 自分より **描画優先度が低い** 描画パーツ | 自分より **描画優先度が高い** 描画パーツ |
| 典型的な見え方 | 形状の **外側** を残す | 形状の **内側** に収める |

「マスク」は専用パーツ種別が単独で持つ機能、「クリッピング」は描画パーツが付帯的に持つ機能、という非対称な関係です。

### 1-2. パーツの役割と `mask_influence`

各パーツは「writer か」「対象か」で役割が決まります。「マスク機能」を持つのはマスクパーツのみですが、一部の描画パーツ種別は共通フラグ **`draw_as_mask`** によって **マスクパーツの役割に変わる**（pure マスク化）ことができます。オーサリングでは種別ごとの設定ですが、ssab では `PartData.draw_as_mask` 1つに集約されるため、下表の Shape/Text/Nines は同一条件になります。

| パーツ種別 | 既定の役割 | pure マスク化条件 | クリッピング (`mask_write`) を持てるか |
|---|---|---|---|
| **マスク** (`PartTypeMask`) | 常に pure マスク | （常に） | — |
| **通常** (Normal) | 描画 | （pure マスクになれない） | ○ |
| **メッシュ** (Mesh) | 描画 | （pure マスクになれない） | ○ |
| **シェイプ** (Shape) | 描画 | `draw_as_mask == 1` | ○ (`draw_as_mask == 0` 時) |
| **テキスト** (Text) | 描画 | `draw_as_mask == 1` | ○ (`draw_as_mask == 0` 時) |
| **ナインスライス** (Nines) | 描画 | `draw_as_mask == 1` | ○ (`draw_as_mask == 0` 時) |

> **シェイプの特例**: `draw_as_mask == 1` でマスク化されたシェイプは Cell（テクスチャ）を持たないため、後述のカットアウト閾値（[§2-5](#2-5-カットアウト閾値被覆に書く画素の範囲)）は効きません。**形状全体がマスク**になります。

Player 側の writer 判定ロジックは概念的に次のようになります：

```
pure_mask   = PartTypeMask || draw_as_mask
is_writer   = pure_mask || mask_write          // ステンシルに書く全パーツ
is_clipping = mask_write && !pure_mask         // 色も描く（高優先度に適用）
```

#### `mask_influence` の二重定義（重要）

`mask_influence` は同一フィールドですが、パーツの **役割で意味が変わります**。`mask_influence` は [§2](#2-判定ルール) のいくつかのルールで登場するため、先にここで意味を確定させておきます。Player は役割ごとに使い分けてください。

| 役割 | `mask_influence` の意味 |
|---|---|
| **マスクパーツ（writer 専任）** | **OP**。`0` = 増分 / `1` = 反転（[§2-3](#2-3-opステンシルへの書込演算)） |
| **描画パーツ（対象側、writer ではない）** | **マスク対象フラグ**。`1` = 適用される / `0` = オプトアウト（[§2-2](#2-2-マスクの効果のオプトアウト)） |
| **クリッピング（writer 兼 描画パーツ）** | 上記の **両方を同時に兼ねる**。`mask_influence` の **同じ値** が「OP」と「対象フラグ」の両方として解釈される |

クリッピングは「描画パーツでありかつ writer でもある」存在なので、`mask_influence` の値が両方の役割で同時に使われます。たとえば `mask_influence == 1` のクリッピングは：

- **対象フラグ = 1**：自身が他のマスクの影響を受ける（マスクに対する opt-in）
- **OP = 反転**：自身が writer として書き込む際は反転 OP で書く

の二つが同時に成立します。これは仕様上 **同じフィールドを意図的に流用** している設計です。Player 側で値を分けたり、片方の意味を捨てたりしないでください。

## 2. 判定ルール

機能の違い（マスク／クリッピング）はあれど、適用ロジックは以下のいくつかの単純なルールに分解して、統一的に扱うことができます。各ルールで使う `mask_influence` の意味は役割で変わる点に注意してください（[§1-2](#1-2-パーツの役割と-mask_influence)）。

### 2-1. スコープ（どの描画パーツにマスクが及ぶか）

描画優先度を基準に決まります：

- **マスク** → 自分より **描画優先度が低い** 描画パーツに適用（描画優先度が自身を超えるとマスクの効果が自動消滅する）
- **クリッピング** → 自分より **描画優先度が高い** 描画パーツに適用（描画最高優先度まで持続するためマスクの効果は自動消滅しない）

描画優先度の決定（SpriteStudio 共通ルール）：

- 原則 **FrameData の Priority** で決定
- 同着の場合、**パーツ ID（格納インデックス）が高い方が上**（= 描画優先度が高い）

実装上は `draw_order`（Priority 昇順・同着は ID 昇順で並ぶパーツ index 列）の位置 `rank` とした時に:

- マスク: `rank < M`（writer M より前のスコープ）
- クリッピング: `rank > C`（writer C より後のスコープ）

### 2-2. マスクの効果のオプトアウト

- マスクする側（writer）が機能するのは、次の **両方** の条件を満たす必要があります。
    - **`mask != 0`**（`mask == 0` → 何も書かない＝動作せず）
    - **`Hide == false`**（`Hide == true` → 何も書かない）

- 描画パーツがマスクされるのは、次を満たす必要があります。
    - 描画パーツが **`mask_influence == 1` のときのみ** マスク／クリッピングの影響を受けます。`mask_influence == 0` の描画パーツはマスクの影響を受けません（オプトアウト）。

> 補足: `Hide == true` の writer は Brain が draw_order / DrawBatch に含めないため、Player 側で `Hide` を意識する必要はありません。**`mask` 値だけ Player でチェック** してください。

### 2-3. OP（ステンシルへの書込演算）

- **マスクパーツ**: `mask_influence` が OP を兼ねる。`0` = **増分**（`stencil + 1`）/ `1` = **反転**（`~stencil`）
- **クリッピング**: 同じく `mask_influence` が OP を兼ねる（マスクパーツの OP 解釈と同一）。クリッピングは描画パーツでもあるため、**同じ `mask_influence` 値が「対象フラグ」（[§2-2](#2-2-マスクの効果のオプトアウト)）と「OP」の両方として同時に使われる**（詳細は [§1-2](#1-2-パーツの役割と-mask_influence)）

### 2-4. 極性（マスクの内側か外側のどちらに描画するか）

極性は **機能では決まらず、被マスク対象パーツの `visible_inside_mask`** で一律に決まります。

- `visible_inside_mask == 1` → マスクの **内側** に描画
- `visible_inside_mask == 0` → マスクの **外側** に描画
- 判定式: `masked == visible_inside`（true で描画 / false で `discard`）

> 補足: [§1-1](#1-1-マスクとクリッピングは別機能) の表に書いた「マスク = 外側 / クリッピング = 内側」は **典型的なオーサリング既定値** であって、極性そのものは対象側のプロパティです。**対象パーツがマスクとクリッピングの両方のスコープに同時に入る場合も、1 本のステンシル + 対象 1 個の `visible_inside_mask` で判定** します（機能ごとで極性を分けていません）。

### 2-5. カットアウト閾値（被覆に書く画素の範囲）

マスク・クリッピング **共通** で、FrameData の `mask` 値（`0..255`）から決まります。シェーダで処理する想定です：

- 閾値 = `(255 - mask) / 255`
- `mask == 255` → 閾値 0 → **完全透明（α=0）以外のすべての画素** を被覆に書く
- `mask == 0` → 閾値 1.0 → α > 1.0 を要求（あり得ない）→ **何も書かない**（[§2-2](#2-2-マスクの効果のオプトアウト) と整合）

**テクスチャを持たないシェイプ** は閾値の対象外（幾何全体が形になる）。

## 3. 実装方式

### 3-1. GPU ステンシルバッファが使える場合（推奨）

SpriteStudio オリジナルのマスク機構はステンシルバッファに沿った設計です。エンジンがステンシルを公開している場合、それを使うのが最も素直です：

> **メモ**: Unity の Shader Graph などのモダンなノードベースシェーダは、通常ステンシルバッファの細かな出力をサポートしていません。エンジンの制約によっては、マスク処理用のパスだけは手書きのシェーダ（HLSL等）や専用の RenderPass を用いて住み分ける必要がある点に留意してください。

1. `draw_order` を順に走査
2. Writer が来たら：カットアウト閾値で `discard` した残り画素を、OP（増分 / 反転）でステンシル更新
3. 対象描画パーツが来たら：ステンシル値と `visible_inside_mask` で `discard` 判定

#### 3-1-1. Writer と Test の 2 つの役割（ステンシル状態の割り当て）

マスクは 2 種類のドローに分かれます。**Writer**（マスクの形をステンシルに刻む）と、**被マスク対象の Test**（刻まれたステンシルを読んで内外を判定）。

- **Writer**：色は書かない（`ColorMask 0`）。ステンシルは常に更新（`Comp = Always`）、更新演算 `Pass` を OP（[§2-3](#2-3-opステンシルへの書込演算)）で切り替えます：
  - 増分マスク → `IncrementWrap` / `DecrementWrap`（**カウンタ**。ネスト深さぶん数えられ、4 ビットなら 15 段まで）
  - 反転マスク（`mask_influence` の反転指定）→ `Invert`（奇偶＝ winding 方式。自分自身が逆演算）
  - `Ref` は使いません（Replace ではないので `0` で良い）。カットアウトは [§2-5](#2-5-カットアウト閾値被覆に書く画素の範囲) の閾値でフラグメント `discard`（Shape のようにジオメトリ自体がマスクなら閾値を負にして discard 無効）。
- **Test（被マスク対象）**：通常の色描画に**ステンシルテストだけ**を足します。極性（[§2-4](#2-4-極性マスクの内側か外側のどちらに描画するか)）は `Comp` で表現：
  - `visible_inside_mask`（内側に描く）→ `NotEqual`（マスクビットが立っている画素で通す）
  - 外側に描く → `Equal`
  - `Ref = 0`、テストはステンシルを**書きません**（`WriteMask = 0`）。

つまり**極性（内外）は Writer ではなく Test 側**に載ります。

#### 3-1-2. ステンシル状態の保全（描画前後）

素朴には「マスク描画の前にステンシルを退避し、後で復元」したくなりますが、SS のマスクは**演算の対称性で自己相殺**させる設計なので、明示的な退避/復元やクリアパスは不要です：

- **pure マスク**：全ボディパーツより前に increment（前処理）し、**自分の `draw_order` rank で同じ形を decrement**します。これでフレーム内の正味の寄与が**ゼロ**に戻り、かつ「マスクは自分より優先度の低い（後の）パーツにだけ効く」スコープ（[§2-1](#2-1-スコープどの描画パーツにマスクが及ぶか)）が自然に出ます。反転マスクなら `Invert` を 2 回で同じく相殺。
- **クリッピングマスク**：自分の rank で書き込み、**そのオブジェクト（アニメ）の全描画を終えた後**に同じ形で逆演算して相殺します。クリップ対象（自分より後のパーツ）はすべて描き終えてから戻すので、**オブジェクト内の見え方は不変**のまま、正味の寄与はオブジェクトの描画後に**ゼロ**へ戻ります。反転マスクなら `Invert` を 2 回。
    - **この相殺は省略できません**。ステンシルバッファはカメラ/フレーム開始時にクリアされますが、それは**フレーム先頭で 1 回だけ**です。同一フレーム内に複数の SS オブジェクトを描くと**オブジェクト間ではクリアされない**ため、クリッピングのビットを残したままにすると、その残留が後続オブジェクトのマスクテストを汚染します（下の [§3-1-3](#3-1-3-エンジンがステンシルを常用する場合urp-等の回避策) のビット隔離は URP 等の他用途からは守りますが、**同じビット範囲を使う別の SS オブジェクトからは守りません**）。末尾で相殺すればフレームをまたいだ汚染もオブジェクト間の汚染も起きません。

要点は **「クリアや save/restore ではなく、増減の対称性でオブジェクトの描画内に状態を閉じる」** こと（pure マスクは自分の rank で、クリッピングは自分のオブジェクトの描画末尾で相殺）。コストは相殺用にジオメトリをもう一度ビルドするだけで、マスクは数が少ないので軽微です。

#### 3-1-3. エンジンがステンシルを常用する場合（URP 等）の回避策

URP をはじめ多くの描画パイプラインは、**ステンシルを自前の用途で常時使用**します（ライト、Decal、Rendering Layers、SSAO、deferred のマテリアル種別、カメラスタッキング等）。この上に SS のマスクを素で重ねると相互破壊が起きます。

回避策は **`ReadMask` / `WriteMask` で SS マスク専用のビット範囲に隔離**することです。ForUnity の実例では **下位 4 ビット（`0x0F`）** に限定しています：

- これは URP の user-reserved 割り当て（bit 0–3 = UserMask / bit 4 = light / bit 5–6 = material type / bit 7 = reserved）の**空きビット**に一致するため、URP の各機能と共存できます（Built-in パイプラインも同レイアウト）。
- `WriteMask = 0x0F`：`IncrementWrap` の桁上がりが bit 4（URP の light ビット）へ**漏れません**（マスクで落とされる）。
- `ReadMask = 0x0F`：テストは**自分のビットだけ**を見るので、URP が bit 4–7 に書いた値を無視できます。
- カウンタ方式（Incr/Decr）なら 4 ビットでネスト 15 段、反転方式なら奇偶。ビット幅を **`0x0F` より広げると URP の予約ビットを破壊（＆され）る**ので注意。

> 移植先パイプラインがステンシルを使う場合は、同様に**専用のビット範囲を選んで Read/Write マスクで囲う**のが定石です。ビットを確保できない、あるいはステンシル自体が公開されていないエンジンでは、[§3-2](#3-2-ステンシルが公開されていないエンジンの場合) の被覆ビットマップ方式（ステンシル非使用）へ切り替えます。

### 3-2. ステンシルが公開されていないエンジンの場合

例として Godot 4.6 の 2D canvas はステンシルバッファを公開していません。このようなエンジンでは、以下のハイブリッド方式でステンシルを再現できます：

1. **被覆ビットマップの生成**: フレーム毎に、その時の全マスク writer をオフスクリーンの被覆ビットマップへラスタライズ。各 writer に 1 ビットを割り当て、被覆する画素にそのビットを立てる。
2. **描画時の replay**: 被マスク対象は描画シェーダ内で被覆ビットマップをサンプルし、アクティブな writer を draw_order 順に replay してステンシル状態を再構成、`discard` で内外をクリップする。

要点は **「描画時刻に依存する状態を持たず、被覆（writer の形）と replay（対象側の再構成）に分離する」** こと。被覆 1 枚で 24 writer まで扱えるエンコード（RGBA8 の RGB チャンネルに 8 bit × 3 = 24 bit）が実用範囲です。

> **被覆ビットマップのサイズについて**：writer 全体の bbox に合わせて動的にスケールし、**長辺を上限値（例：1024 px）に揃える** 実装が実用的です。Full HD クラスの画面でピクセル等倍精度を確保しつつ、1 枚あたり最大 4 MiB（RGBA8）に収まります。アニメーションを多数同時表示する場合は、画面解像度連動や小プール共有でさらに削減できます（最適化案）。

#### 3-2-1. 参考実装（被覆ビットマップ方式の擬似コード）

以下、エンジン非依存の擬似コードで全体の流れを示します。

**データ構造（最大 24 writer、RGBA8 の RGB チャンネルに 8 bit × 3）**

```
const int MAX_WRITERS = 24;

struct MaskWriter {
    int  part_index;     // パーツインデックス
    int  bit;            // 0..23、被覆内のビット位置
    int  draw_rank;      // draw_order 上の rank
    bool op_invert;      // OP: false=増分, true=反転
    bool is_clipping;    // クリッピング（色も描く）
};
```

**Writer 集合の確定（毎フレーム）**

```
function build_mask_writers(frame) -> [MaskWriter]:
    writers = []
    for rank, part_index in enumerate(frame.draw_order):
        part = frame.parts[part_index]
        // part.data.*  = PartData（静的）/ part.frame.* = FrameData（毎フレーム）
        pure_mask  = part.data.type == Mask || part.data.draw_as_mask
        is_writer  = pure_mask || part.data.mask_write
        if not is_writer:               continue
        if part.frame.mask == 0:        continue       // §2-2 opt-out（毎フレーム値）
        if len(writers) >= MAX_WRITERS: break

        writers.append(MaskWriter {
            part_index  = part_index,
            bit         = len(writers),                 // 0,1,2,...
            draw_rank   = rank,
            op_invert   = part.data.mask_influence,     // §2-3 OP（pure マスク・クリッピング共通）
            is_clipping = part.data.mask_write && !pure_mask,
        })
    return writers
```

**被覆ビットマップ生成（毎フレーム）**

オフスクリーンの RGBA8 viewport に additive blend で各 writer の幾何を描画。disjoint な bit が OR されるよう、各 writer は自分の bit だけが立つ色で描画します。

```
function render_coverage_bitmap(writers, frame) -> Bitmap:
    bitmap = create_offscreen_RGBA8_with_additive_blend()
    for w in writers:
        channel   = w.bit / 8                          // 0=R, 1=G, 2=B
        bit_val   = (1 << (w.bit % 8)) / 255.0
        bit_color = vec4_zero_except(channel, bit_val)
        threshold = (255 - frame.parts[w.part_index].frame.mask) / 255.0  // mask は float

        draw_geometry(
            geometry = geometry_of(w.part_index),       // Normal=sprite / Mesh / Shape
            shader   = MASK_WRITE_SHADER,
            uniforms = { mask_bit_color: bit_color, mask_threshold: threshold }
        )
    return bitmap
```

**ビット書込みシェーダ（GLSL）**

```glsl
uniform vec4  mask_bit_color;   // 該当 RGB チャンネルに pre-encode されたビット
uniform float mask_threshold;   // (255 - mask) / 255

void fragment() {
    // §2-5 カットアウト: α が閾値を超える画素のみ被覆へ
    if (texture(TEXTURE, UV).a <= mask_threshold) discard;
    // additive blend が src.rgb * src.a で動くので、alpha=1 が必須
    COLOR = vec4(mask_bit_color.rgb, 1.0);
}
```

**描画時の replay（被マスク対象シェーダ、GLSL）**

```glsl
uniform sampler2D coverage;
uniform int   mask_count;
uniform vec4  mask_meta[MAX_WRITERS]; // (draw_rank, bit, op_invert, is_clipping) ※ build_mask_writers の MaskWriter と対応
uniform float this_rank;
uniform float visible_inside;         // §2-4 極性（1=内側 / 0=外側）

bool mask_passes(vec2 cov_uv) {
    if (mask_count == 0) return true;
    // bbox 外は writer 無しと同じ扱い（端の CLAMP による誤マスク回避）
    if (cov_uv.x < 0.0 || cov_uv.x > 1.0 || cov_uv.y < 0.0 || cov_uv.y > 1.0)
        return visible_inside <= 0.5;

    vec4 cov = texture(coverage, cov_uv);   // sampler は nearest 必須
    int stencil = 0;
    for (int i = 0; i < mask_count; i++) {
        vec4 m = mask_meta[i];
        bool is_clipping = m.w > 0.5;
        // §2-1 スコープ判定（クリッピング=自分より後 / マスク=自分より前）
        bool active = is_clipping ? (this_rank > m.x) : (this_rank < m.x);
        if (!active) continue;
        // 被覆からこの writer のビットを抽出
        int bit  = int(m.y + 0.5);
        int byte = int(cov[bit / 8] * 255.0 + 0.5);
        if (((byte >> (bit % 8)) & 1) == 0) continue;
        // §2-3 OP
        if (m.z > 0.5) stencil = (~stencil) & 0xFF;     // 反転
        else           stencil = (stencil + 1) & 0xFF;  // 増分
    }
    bool masked = (stencil != 0);
    return masked == (visible_inside > 0.5);            // §2-4 判定式
}

void fragment() {
    // ... 通常の色合成 ...
    if (!mask_passes(coverage_uv)) discard;
    COLOR = ...;
}
```

**実装上の注意**

- **被覆 sampler は nearest 必須**（LINEAR だと隣接ビットがブレンドして誤復号）
- **bbox 外は `visible_inside` だけで分岐**（writer 無し相当として扱う）
- `mask_meta[i].x`（= writer 自身の `draw_rank`）を、対象の `this_rank` と前後比較する（[§2-1](#2-1-スコープどの描画パーツにマスクが及ぶか) スコープ判定）

#### 3-2-2. 被覆 UV の導出とインスタンス（サブアニメ）への継承

**被覆 UV の導出**: replay シェーダの `coverage_uv` は、頂点ステージで **被マスク対象の player-local 座標を被覆 UV `[0,1]` へ写すアフィン変換** `M`（[§3-2](#3-2-ステンシルが公開されていないエンジンの場合) の bbox 正規化＝ basis 2x2 ＋ offset）で求めます。被覆ビットマップは「マスク writer を所有するアニメ」の bbox に張られるため、`M` はそのアニメの player-local 空間が基準です。

**インスタンス（サブアニメ）への継承**: SpriteStudio のマスクは、被マスク対象が **インスタンスパーツ（サブアニメ参照）** の場合、**そのサブアニメ全体**へ及びます。被覆とメタは親アニメが所有するので、子へ次のように引き渡して replay します。

1. 親が自分の **被覆テクスチャ・`mask_meta`・writer 数** をインスタンス子の Player へ渡す。
2. UV 変換を合成する: `M_child = M_parent · slot_xf`（`slot_xf` = 子-local → 親-local のインスタンス配置行列）。これで子の各頂点の player-local 座標が **親の被覆 UV** に正しく写る。
3. サブアニメ全体を **インスタンスパーツ自身の `rank` と `visible_inside_mask`** で一括判定する（子の個々のパーツ単位では評価しない）。

要点:

- **継承は単段（1 階層）**。インスタンスは「1 個の被マスク対象」として扱う。
- 継承が働くのは、インスタンスパーツが **マスク対象（`mask_influence == 1` または `mask_write`）かつ親マスクのスコープ内（または `visible_inside`）** のときのみ。
- 子は親の被覆を参照するだけで、自前の被覆は生成しない（子が自分のマスクを持つ場合はそれとは別系統）。

#### 3-2-3. 被覆ビットマップのサイズクラスと 1 フレーム遅延（連続スケール時の対策）

[§3-2](#3-2-ステンシルが公開されていないエンジンの場合) の「被覆ビットマップのサイズについて」（bbox に合わせて動的スケール）を、オフスクリーンターゲットを **プールで使い回しながら** 実装する際の、連続的に拡大・縮小するマスク特有の注意点です。基本方式はこの節が無くても動きますが、マスクを激しく連続ズームさせると 1 フレームだけマスクが抜けて見えることがあり、その対策を述べます。

**サイズクラス（2 の冪への量子化）**

bbox のピクセルサイズをそのまま毎フレーム target サイズにすると、target を毎フレーム再確保することになり非効率です。実用上は、各軸のサイズを **2 の冪の「サイズクラス」へ切り上げ**（例：… / 256 / 512 / 1024）、そのクラスの target をプールから借ります。フットプリントがクラス境界（クラス `C` は `C/2 < px ≤ C` を担当）を跨いだときだけ別クラスの target に切り替えるので、滑らかに拡縮する通常ケースでは target が使い回され再確保が起きません。

サンプリング側の UV は [§3-2-2](#3-2-2-被覆-uv-の導出とインスタンスサブアニメへの継承) の `M`（bbox 正規化）で **サイズクラス非依存**（同じ player-local 空間の bbox を常に `[0,1]` に写す）なので、どのサイズクラスの被覆を貼っても対象は正しくクリップされます。

**1 フレーム遅延と「サイズクラス遷移時の 1 フレーム抜け」**

多くのエンジンでは、オフスクリーンターゲットは **1 フレーム遅延** でしかサンプルできません（今フレームに描いた被覆は次フレームで読める。例：Godot の Viewport テクスチャ）。通常はマスクが内容に 1 フレーム遅れるだけで無害です。

問題はサイズクラスが変わる **遷移フレーム** です。新しいサイズの target を借りると、その target には **まだ有効な被覆が無い**（未描画、または別用途の残像）。1 フレーム遅延のため今フレームには読めず、そのままだと **このフレームだけマスキングが無効** になり、クリップ対象が無クリップで描かれてマスクが一瞬抜けます。連続ズームでは境界を跨ぐたびにチラつきます。

**対策 1：遷移フレームは旧 target をサンプル（軽量ダブルバッファ）**

サイズクラス遷移時、旧 target を即解放せず **1 フレームだけ保持** し、その遷移フレームは **旧 target の（前フレームに描いた）被覆をサンプル** します。UV は bbox 相対でサイズクラス非依存なので、旧 target（前の解像度）でも対象は正しく写り、これは **通常フレームと同じ 1 フレーム遅延**（その 1 フレームだけ前の解像度）に過ぎません。マスクは抜けません。新 target には今フレームの被覆を描いておき、次フレームからそちらへ切り替えます。

**対策 2：縮小側ヒステリシス（境界バタつき対策）**

フットプリントがクラス境界付近で揺れると、量子化がクラスを毎フレーム反転させ（512↔1024…）遷移が乱発します。これを防ぐため **縮小の判定にデッドバンド** を設けます：拡大は即応（解像度を落とさない）、縮小は境界を **十分に下回るまで現クラスを維持** します。非対称なのは、拡大を渋ると被覆解像度不足で縁が荒れる（見える品質劣化）一方、縮小の居座りは VRAM が少し増えるだけ（見えないコスト）だからです。

> **デッドバンド幅の目安**：この比率はチューニングノブで唯一の正解値はありません。Godot リファレンス Player は初期値 `0.15`（境界の 15% 下回るまで現クラス維持）を採用しています。境界振動での遷移をさらに減らしたければ上げ、小さいマスクが一段大きい target に長く居座る VRAM が気になれば下げる、という調整幅として扱ってください。

対策 1 が「遷移が起きても抜けない」、対策 2 が「そもそもムダな遷移を減らす」を担い、補完します。

### 3-3. 共通の注意点

- **pure マスクは色を描かない**: マスクパーツ（と pure マスク化された描画パーツ）の色描画バッチはスキップしてください。
- **writer 数の上限**: ステンシル幅 / 被覆エンコードのビット数で writer 上限が決まります。実用上は 1 フレームあたり数個〜数十個に収まります。
- **被覆方式の bbox 外の扱い**: 被覆ビットマップ方式の場合、bbox 外の対象パーツは「writer 無し」と同じ扱い（マスクされない）にすることで、テクスチャ端の CLAMP による誤マスクを避けられます。

## 4. 実装チェックリスト

実装漏れの自己点検用。各項目の根拠は対応する節を参照してください。

- [ ] **役割判定**（[§1-2](#1-2-パーツの役割と-mask_influence)）: `pure_mask = PartTypeMask || draw_as_mask` / `is_writer = pure_mask || mask_write` / `is_clipping = mask_write && !pure_mask` の 3 式で分類した。
- [ ] **読み出し元**（用語表）: `mask_influence` / `mask_write` / `visible_inside_mask` / `draw_as_mask` を **PartData（静的）** から、`mask` / `Priority` / `Hide` を **FrameData（毎フレーム）** から読んでいる。
- [ ] **writer 無効化**（[§2-2](#2-2-マスクの効果のオプトアウト)）: `mask == 0` の writer はスキップした（`Hide` は draw_order に含まれないので Player では未チェックでよい）。
- [ ] **オプトアウト**（[§2-2](#2-2-マスクの効果のオプトアウト)）: 対象描画パーツは `mask_influence == 1` のときのみ影響を受ける。
- [ ] **OP**（[§2-3](#2-3-opステンシルへの書込演算)）: `mask_influence` を `0`=増分 / `1`=反転 として、pure マスク・クリッピング共通で適用した。
- [ ] **極性**（[§2-4](#2-4-極性マスクの内側か外側のどちらに描画するか)）: 機能ではなく **対象パーツの `visible_inside_mask`** で `masked == visible_inside` を判定した。
- [ ] **スコープ**（[§2-1](#2-1-スコープどの描画パーツにマスクが及ぶか)）: マスク=自分より rank 小、クリッピング=自分より rank 大の対象に適用した。
- [ ] **カットアウト閾値**（[§2-5](#2-5-カットアウト閾値被覆に書く画素の範囲)）: `(255 - mask) / 255`（`mask` は float）で被覆に書く画素を絞った。テクスチャを持たないシェイプは閾値対象外。
- [ ] **ステンシル状態の保全**（[§3-1-2](#3-1-2-ステンシル状態の保全描画前後)・GPU ステンシル方式）: pure マスクは自分の rank で、**クリッピングは自分のオブジェクトの描画末尾で**、書き込みと同じ形を逆演算して相殺した（同一フレーム内の他 SS オブジェクトへの汚染防止）。
- [ ] **pure マスクの色描画スキップ**（[§3-3](#3-3-共通の注意点)）: マスクパーツ／pure マスク化パーツの色バッチを描いていない。
- [ ] **インスタンス継承**（[§3-2-2](#3-2-2-被覆-uv-の導出とインスタンスサブアニメへの継承)）: 被マスク対象がインスタンスなら、サブアニメ全体を 1 対象として親の被覆・メタで一括判定した（単段のみ）。
