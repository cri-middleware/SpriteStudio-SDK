# 外部リソースとテクスチャの管理

大規模なプロジェクトや動的な演出で必要となる、外部リソースの差し替え・参照の実装ガイドです。

## テクスチャの解決: `texture_hash` は 2 つのハッシュ空間を持つ

描画時にバインドすべきテクスチャは、常に `DrawBatch` の `texture_hash()` から決まります。ただしこの値は、**2 種類のハッシュ空間**のどちらかです。

| `texture_hash` の出どころ | 対応する ssab のエントリ | 発生条件 |
|---|---|---|
| セルマップ名のハッシュ | `cellmaps()[].name_hash` | 通常（既定） |
| テクスチャ **ファイル名** のハッシュ | `external_textures()[].name_hash` | そのパーツに作画上のテクスチャ変更 (`TCHG`) が効いているとき |

> **セルマップ名に拡張子は含まれません**。`common.ssce` のセルマップ名は `common` で、そのハッシュは `fnv1a("common")` です。一方 `TCHG` が指すのはテクスチャのファイル名（`common.png` など）なので `fnv1a("common.png")` になります。両者は文字列が違う以上まったく別の値であり、**Player のテクスチャマップは両方をキーとして保持する必要があります**。

したがって初期化時は `cellmaps()` と `external_textures()` の **両方** をロードし、それぞれの `name_hash()` をキーに同じマップへ格納してください（[データのロードと初期化](../30_core/10_initialization.ja.md) §3）。この 2 つのテーブルを引ければ、`texture_hash` は必ず解決できます。`TCHG` が名指しした全てのテクスチャ名が `external_textures()` に含まれることは、コンバータが保証しています。

## 作画で指定されたテクスチャ変更 (TextureChange / `TCHG`)

SpriteStudio のアトリビュート「テクスチャ変更」は、パーツが参照する **セルはそのままに、サンプリング先のテクスチャだけを差し替える** 機能です。同じレイアウトで色違い・衣装違いのアトラスを用意しておき、作画側（タイムライン）で切り替える用途で使います。

### Player の実装は原則不要

ランタイムはこのアトリビュートを評価したうえで、その値を **`DrawBatch` のバッチキーに折り込みます**。結果として:

- 上書きが効いているパーツは、同じセルマップを参照する他のパーツと **同じバッチにまとめられません**（別バッチに分割されます）。
- 各バッチの `texture_hash` は、そのバッチが実際にバインドすべきテクスチャを指します。

つまり **`texture_hash` をキーにテクスチャをバインドする通常の描画ループのままで、テクスチャ変更は正しく描画されます**。パーツ単位で状態を読んでバッチを切り直すような実装は必要ありません。必要なのは前節のとおり、`external_textures()` をロード済みであることだけです。

### 仕様

| 項目 | 挙動 |
|---|---|
| 補間 | **なし（ステップ評価）**。キーの打たれたフレームで切り替わり、次のキーまで保持されます。 |
| 空のテクスチャ名 | 作画上の「上書きしない」。ssab には `0` として格納され、パーツは自身のセルのテクスチャを使います（実テクスチャのハッシュと衝突しません）。 |
| 対象パーツ | **セルを解決したパーツ**（`Normal` / `Nines` / `Mesh` / `Mask`）。セルを持たない種別（`Shape` / `Text` / `Instance` / `Effect`）は `texture_hash == 0` のままです。 |
| セルの矩形・UV | **変わりません**。`ss_runtime_get_local_uvs` / `ss_runtime_get_cell_meta` は、元のセルマップのピクセル空間の値を返し続けます。 |

> [!IMPORTANT]
> **差し替え先テクスチャのサイズ**: ランタイムが返す UV とセル矩形は、元セルマップのピクセル座標のままです。Player は通常これを「バインドしたテクスチャのサイズで割って」正規化しますが、その場合 **差し替え先が元セルマップと違う解像度だと、同じピクセル矩形＝絵としては別の領域** をサンプリングすることになります。テクスチャ変更は「同じサイズ・同じレイアウトのアトラスに差し替える」使い方が前提です。

### `PartState.texture` について

`FrameData` の `parts[].texture` にも同じ値（テクスチャ名の fnv1a ハッシュ、上書き無しなら `0`）が入っています。`UpdateAttributeFlags::AttributeTexture` が立っているときだけ有効です。

バッチ描画をする Player がこれを読む必要はありません。パーツごとにエンジンのノードを作る `RenderMode::SceneGraph` 方式など、`DrawBatch` を使わない実装だけが参照してください。

### 注意点

- **バッチ数はフレームごとに変わります**。テクスチャ変更のキーが切り替わるたびに分割のされ方が変わるため、「バッチ数は一定」という前提を置いた最適化（バッファの使い回しなど）は破綻します。[パーツオーバーライド](./65_override_layer.ja.md) のセル差し替えと同じ注意点です。
- **`external_textures()` は「作画者が登録した外部テクスチャ」の一覧ではありません**。`TCHG` が名指ししたテクスチャ名（`common.png` のような、セルマップ自身の画像を含む）も、Player がハッシュから名前を逆引きできるようコンバータが追加します。このリストを「差し替え可能なテクスチャ」として UI に出している Player では、表示されるエントリが増えます（いずれも差し替え対象として妥当なものです）。

### 検証

`tests/overall/TextureChange.ssae` を使います。2 つのパーツ（`TO_TEXTURE` / `TO_CELLMAP`）が同じ `common` セルマップを参照し、フレーム 1 でそれぞれ別のテクスチャへ切り替わります。エディタと同じ絵になり、かつそのフレームで **バッチが 2 つに分かれている** ことを確認してください。

## 実行時のテクスチャ差し替え (Player 側のオーバーライド)

作画ではなく、**プログラムから** 実行時にテクスチャを差し替える機能です（衣装替え、動的な表情差分など）。これは Player 側の責務で、[Override Layer API](./65_override_layer.ja.md) には含まれません。

- **実装方法**: Player 側で `texture_hash` をキーとしたテクスチャオブジェクトのマップを保持します（前節のとおり、セルマップ名と `external_textures` の両方のハッシュが入ります）。
- **解決手順**:
    1. 初期化時に通常通り SSAB の定義に従ってテクスチャをロードし、マップに格納します。
    2. プログラムから特定のキーに対して別のテクスチャオブジェクトを上書き（オーバーライド）します。
    3. **オーバーライドの解除（復元）**: オーバーライドに `nullptr` (または `null`) が指定された場合は、SSAB に定義されているオリジナルのテクスチャパス（`cellmaps()` の `image_path`、または `external_textures()` の `name`）から画像を再ロードし、マップの状態を初期値に復元します。
    4. 描画時、`DrawBatch` の `texture_hash()` をキーにマップから対象のテクスチャをルックアップして描画処理に渡します。これにより、元のデータを変更せずに衣装替えや動的な表情変更が可能になります。

```cpp
// テクスチャのオーバーライド（差し替え）の実装例 (C++)
void Player::set_cellmap_texture(const std::string& cellmap_name, Texture* override_texture) {
    uint32_t name_hash = fnv1a_hash(cellmap_name); // cellmap 名のハッシュ値を取得

    if (override_texture != nullptr) {
        // 1. 指定されたテクスチャでマップを上書き
        textures_map[name_hash] = override_texture;
    } else {
        // 2. 解除時の処理: SSAB 内の定義からオリジナル画像を再ロードして復元
        auto cellmaps = ssab_binary->cellmaps();
        for (uint32_t i = 0; i < cellmaps->size(); i++) {
            auto cellmap = cellmaps->Get(i);
            if (cellmap->name_hash() == name_hash) {
                // 相対パス解決を行い、オリジナルのテクスチャを再ロード
                std::string original_path = resolve_path(cellmap->image_path()->c_str());
                textures_map[name_hash] = Engine::load_texture(original_path);
                break;
            }
        }
        // 見つからなければ external_textures() 側も同様に探して復元する
    }
}
```

> テクスチャ変更 (`TCHG`) が効いているパーツは、そのフレームだけ別のハッシュでバインドされます。差し替え対象のキーがそのハッシュでなければ、上書きは効きません（作画側の指定が優先される形になります）。

## 外部 SSAB 参照 (External Instance)
インスタンスパーツが「別の SSAB ファイル」にあるアニメーションを参照する機能です（[インスタンスパーツ](./10_instance.ja.md) と併せて参照）。
- **実装方法**: 
    1. 親の SSAB の `external_instances()` セクションを走査し、参照されている外部 SSAB 名をリストアップします。
    2. それらのファイルをロードし、個別の `Resource` オブジェクトとして管理します。
    3. インスタンスパーツのセットアップ時、`ref_anime_hash` をキーに全ロード済み SSAB を検索して対象のアニメーションを見つけ出し、子 Context を初期化します。
