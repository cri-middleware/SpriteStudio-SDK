# 実装フェーズ 6：イベントシステムの実装

アニメーション中に発生する「ユーザーデータ」「シグナル」「サウンド」などのイベントを Player 側で処理する方法です。

## 1. イベントデータの取得方法
libssruntime の `update` で時間を進める際、フレームスキップが発生したり、再生方向が変わったりすることがあります。

- **取得ロジック**: 前回のフレーム番号を保存しておき、現在のフレーム番号との間にあるすべてのフレームをチェックします。
- **フレーム跨ぎの注意**: `last_frame` から `current_frame` までの区間を走査し、その中に存在するイベントデータを抽出してください。

## 2. ユーザーデータコールバック (UserData)
アニメーションに埋め込まれた数値、座標、文字列などのデータです。

- **発火**: アトリビュート内の `UserData` が存在するフレームに到達した際、Player 側で定義したコールバック関数を呼び出します。

## 3. シグナル (Signal)
特定のコマンドやパラメータを外部に通知するための仕組みです。

- **実装**: シグナルコマンド ID と、付随するパラメータ（Bool, Integer, Floating, Text）を取得して、対応する処理を実行します。

## 4. この段階での動作確認 (Validation)
時間経過に伴うイベントの取得が正しいかを確認します。

- **確認対象**: `UserData.ssae`
    - **チェック内容**: 指定されたフレームで期待通りのユーザーデータ（文字列、数値等）がコールバックとして発火するか。
- **確認対象**: `Signal.ssae`
    - **チェック内容**: シグナルコマンドの受信とパラメータのパースが正しく行えているか。
